# Invisible Localization — status

> Guide: [docs/tools/localization.md](../tools/localization.md) · Agent: none yet (launcher tool — closest owner `.claude/agents/launcher-studio.md`)

**One-line state:** shipped — in-launcher, project-scoped string table with batch translate → unreviewed → human-review → save to R2; needs a translation provider configured (Anthropic, or any OpenAI-compatible endpoint).

## Current state

Live in the launcher at `/localization` (granted to `developer` + `artist`; `admin` always), scoped to the **active project**. A single Claude call + R2 storage — no external service, no DB table.

- **Table** — a spreadsheet-style view of the game's text. **Auto-collected sections** harvest every localizable string, source read-only (the owning tool edits it): **per-screen** from the Scene Editor (text nodes, component `text`/`label` params, and text authored inside custom components); a **Win text** section from Invisible Win Text's templates (incl. the built-in info-bar toast defaults); a **Symbol names** section from the Invisible Symbols State Machine's display names (`H1` → "Banana"/"Bananas"); a **Flow messages** section from Invisible Flow's `textMessage` nodes; a **Bet modes** section from Invisible Game Config's bet-mode copy (buy-feature card title/description/button, confirm-dialog body, HUD bet badge); and a **Game UI** section carrying the engine's own coded chrome. Each string's translation key **is the source text**, so identical strings share one translation. A **manual** section holds hand-authored rows (editable `key` + `source`). A **No longer in scenes** section surfaces removed-but-translated rows.
  - Symbol-name rows key on the **trimmed** name (unlike scene/win text, keyed on the exact literal): `resolveSymbolName` trims before it calls the resolver, so a padded key would never match. Only _authored_ names harvest — an unnamed symbol resolves to its bare id and must never become a row; numeric-only names ("7") are skipped.
- **Global settings** — source language, target languages, an optional context/glossary that guides every translation, and a **Never translate** list (comma-separated terms kept verbatim in every language).
  - Not a prompt instruction: each occurrence is **masked** to a `{{DNTn}}` token before the request and the ORIGINAL matched text is restored after it (`localizationMask.ts`), so the model translates the sentence around the term and physically cannot localize the term. Case-insensitive, whole-word, longest-term-first; the restore keeps the source's own casing. Verified offline (16 assertions, `tsx`).
- **Batch translate** — "Translate this row" / "Translate all missing" batches the selected strings + target langs into **one** call, returning strict JSON. Results land **unreviewed** (amber dot) — never auto-saved. Two interchangeable providers (`translate.ts`), same prompt and same JSON contract: **Anthropic** (`claude-sonnet-4-6`, with a **prompt-cached** system prompt of fixed instructions + your glossary), or **any OpenAI-compatible `/chat/completions` endpoint** when `LOCALIZATION_LLM_BASE_URL` + `LOCALIZATION_LLM_API_KEY` are set (which wins if both providers are configured). The OpenAI path sends `response_format: json_object` and retries once without it on a 400, since some providers reject the field.
- **Review + save** — editing a cell (or clicking its dot) marks it reviewed (green); nothing persists until **Save**. On save, auto-collected rows with no translation are **not** stored (re-derived from `editor/<projectKey>/scenes.json` each load, so the table self-heals); translated rows are kept.
- **Storage** — one JSON doc per project in R2: `localization/<projectKey>/strings.json` (`sourceLang`, `targetLangs`, `context`, `protectedTerms[]`, `entries[]` with `origin: editor|winText|symbols|manual`; anything not `manual` is an auto origin — re-derived each load, untranslated ones not persisted). R2-only, no migration.
- **Engine consumption** — the engine's text resolver swaps translations in-game by source-text key (reviewed-only).

  - **Bet modes** harvest from `resolveBetModes`, i.e. the RESOLVED copy the game renders — so the derived defaults a config never overrides (`BUY`/`PLAY`/`ACTIVATE`, a title falling back to the mode key) are translatable too. Only the `base` mode's bet badge is taken; its title/description/button have no surface (the buy menu lists non-default modes only).
  - **Game UI** is the one PROJECT-INDEPENDENT section: it reads `engine-layout`'s `UI_TEXT` registry, which is also where the two `i18nDerived` maps (`components-ui-pixi`, `components-ui-html`) and `apps/lines`' `infoManifest.rules` take their literals — so the list cannot drift from what the game renders. Add a coded label to `UI_TEXT` and it becomes translatable everywhere at once.

## Blocked (owner / external)

- **A translation provider on the launcher's Railway service.** Secret, no code default; until one is set the tool loads and edit/save work, but Translate returns a clear "No translation provider configured" error. Either `ANTHROPIC_API_KEY` (a Claude **API** key — a separate paid account from the owner's Claude subscription, which is why the OpenAI-compatible path exists), or all three of `LOCALIZATION_LLM_BASE_URL` + `LOCALIZATION_LLM_API_KEY` + `LOCALIZATION_LLM_MODEL` to run on a free tier. Also: pick default target languages per project.

## Recent changes

- 2026-08-18 — **"Never translate" list** (`protectedTerms`). Brand/mechanic names ("Free Spins", the game's title) came back localized in every language. Implemented as MASKING, not as a prompt request: `localizationMask.ts` swaps each occurrence for `{{DNTn}}` before the call and restores the original matched text after, so a model translating the surrounding sentence never sees the term. Case-insensitive + whole-word matching, longest term first, restore keeps the SOURCE's casing (`FREE SPINS` ≠ `Free Spins` share nothing); the unmasker also tolerates a model re-emitting `{{ DNT 0 }}` or a bare `DNT0`. Both providers get the extra system block. New comma-separated field under context/glossary; stored in `strings.json`. Applies at translate time only — existing translations need a retranslate.
- 2026-08-18 — **two whole classes of game text were never harvested.** (a) **Bet-mode copy** — the buy-feature cards' title/description/button, the confirm dialog's body and the HUD bet badge live in Invisible Game Config, and the card is ONE `featureCard` def whose text nodes bind `engineProvided` params fed per-mode at RUNTIME; the scene walk deliberately skips `engineProvided` binds, so the cards stayed English in every locale (reported from a French build showing three English cards). New `harvestBetModeText` + `Bet modes` section (`origin: 'gameConfig'`). (b) **The engine's own coded chrome** — `BALANCE`/`WIN`/`BET`, the menus, bet menu, settings + autoplay modals, and the info page's rules copy all render through `translate()` but were never LISTED, so they were untranslatable for any language the code catalogs ship no entry for — and those ship `en`/`zh` only. New `UI_TEXT` registry in `engine-layout` (the single home both `i18nDerived` maps and `infoManifest.rules` now read their literals from) + `harvestUiText` + `Game UI` section (`origin: 'uiText'`, project-independent). Also fixed: `HudReadout` rendered an authored `betAmountLabel` RAW while its `HudCaption`/`LabelBet` siblings translated it. Offline fixture: `scripts/verify-bet-mode-localization.mts` (41 assertions — incl. a negative proving the scene walk genuinely cannot see the card copy).
- 2026-08-17 — **Runtime-mode merge wired — open item #1 closed, and a second bug behind it.** Translations were reaching the browser and being thrown away: the merged Lingui catalog was built at module-eval, before `prepareRuntimeBundle()`, so it always captured the EMPTY baked map. Now `getMessagesMap()` (lazy, uncached). Behind it sat a second gap this tool's own harvest implies: `/localization` collects component **`label` params** (a parametric HUD readout's caption is `params.label`, not a text node), but the engine's text resolver only covered text nodes — so `Balance`/`Win`/`Bet` stayed English even with a complete catalog. `HudReadout`/`HudCaption`/`ButtonLabel` now resolve an authored label. Verified live on Book of Borut Remake (`lang=it` → `Saldo`/`Vincita`/`Puntata`). Detail in [engine.md](engine.md). **Reminder that bit here:** the runtime bundle serves REVIEWED strings only unless the URL carries `ie_authoring=1` — a project whose translations are all unreviewed ships nothing to players and bakes nothing, with no warning in the tool. Worth surfacing an "N translated, 0 reviewed" signal in `/localization`.
- 2026-08-15 — **structured outputs on the OpenAI path**: response format is negotiated strongest-first and steps down only on a 400 — strict per-batch `json_schema` (properties = the requested ids, each with the requested langs, `additionalProperties: false`) → `json_object` → none. Removes the whole class of "model returned a partial/invented row" failures on OpenAI; Google and others land on the `json_object` rung unchanged. Skipped above 100 rows (provider schema-size caps). Also: status messages moved out of the tool bar into a dismissible notice under it (long provider payloads were stretching the bar and a held lease hid messages entirely).
- 2026-08-15 — **Translate never applied anything until now** (`9e27cd0e`). Action results are devalue-encoded — an indexed array where every value is a reference _at every depth_ — and `postAction` in `+page.svelte` resolved only the top level. `translations` decoded to `{ <id>: 2 }` instead of `{ <id>: { it: '…' } }`; `Object.entries(2)` is `[]`, so the apply loop assigned nothing while the UI still said "Translated." Confirmed live (server returned 200 + `{"it":"Hai vinto:"}`, every cell stayed empty), then confirmed fixed live. Now uses SvelteKit's `deserialize`. Also: `error`/`redirect` results carry no `data`, and returning `{}` for them made callers read a failure as a successful no-op — they now surface as errors. **Lesson: don't hand-roll a decoder for a framework's wire format.**
- 2026-08-15 — **provider switch**: `translate.ts` now dispatches to Anthropic _or_ any OpenAI-compatible `/chat/completions` endpoint, so translation can run on a free tier (e.g. Google AI Studio) without an Anthropic API account. Verified offline against a stub provider (19 cases: shaping, unrequested-id/lang rejection, URL join, `response_format` retry, fenced JSON, error surfacing, half-configured fallback, missing-model guard), then live against Google. `LOCALIZATION_LLM_MODEL` has **no code default** — it shipped defaulting to `gemini-2.5-flash`, which Google had already retired _for new accounts_, so the first real use 404'd; a model id is the one bit of this config that reliably rots, so it's now required with an error naming the var.

Also: the built-in **win-text info-bar toast defaults** now harvest even when never retyped (`collectWinTextTemplates` sources toasts via `resolveWinText`).
