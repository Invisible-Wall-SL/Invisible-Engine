## Current state
Live on `main`, owner-verified in the 2026-06-29 pass except the ⏳ items called out below.

- **All three tiers ship** (`/fx`, `fx` tool scope): **A** sprite/flipbook particles from project atlas regions, **B** an emitter pinned onto a bone of a playing Spine backdrop (`SpineBoneAttach`), and **C** whole Spine clips *as* the particles (pooled `SpineParticleBehavior`). The `skeletonKey` key-stability seam for Tier-C shipping is closed.
- **Event trigger end-to-end.** A `trigger.on:'event'` layer fires when a matching cue crosses the runtime event bus (a Flow v1 Broadcast / v2 `fireCue`), with an optional **Stop event** and **Duration**. The full author→ship→fire chain (export → `deploy/effects/` → bake → pull → `bakedEffects()` register) is wired.
- **Pro `/fx` inspector knobs:** emission **direction (centre °) + spread (±°)**, particle **spin min/max + accel**, and a **rotation lock** (`noRotation` — travel along the arc without facing it); a **movement** toggle (eased `moveSpeed` vs **gravity/acceleration** — up-direction + downward gravity = a fountain); **colour** start/end tint **plus a colour overlay with a per-particle intensity min/max**; **blend mode** (Normal/Add/Screen/Multiply); five **spawn kinds** — point / circle / ring / rectangle / **burst** (even fan). Alpha, Scale and the eased Speed each carry an **On** switch (a config with no such behavior can grow one instead of the section silently vanishing) and a **Min / Max** switch that splits each end into a per-particle range. All are live sliders + number boxes that re-tune the preview verbatim.
- **Layer stack ops** — ▲/▼ reorder (list order IS draw order; `FxStage` re-appends the emitter containers in doc order each rebuild so the preview restacks), ⧉ duplicate, and a `localStorage`-backed **⧉ Copy / 📋 Paste** that survives navigation, so a layer moves **between effects**.
- **Flipbook playback is authorable** — an `animated` layer chooses **Match particle lifetime** (`framerate: -1`, the long-standing default) or an explicit **fps + loop**, carried on `art.framerate`/`art.loop` through `bindArt` at all four render sites.
- **Preset library** — per-layer "Apply preset…" (Fountain, Fire, Smoke, Sparks, Explosion-burst, Rain, Snow, Confetti, Magic glow) preserving art/placement/trigger.
- **Rig-timeline direct binding** — on a Rigger event keyframe you pick the effect, its host bone, the SLOT it draws at, and per-binding opacity / size / delay / duration / speed, and a **Continuous** flag that stops a looping clip restarting an ambient burst every lap (`evtObj.fx`), baked to a `rigFx` manifest and played by `RiggedEffect` on the beat (`forceEmit`); the cue-broadcast path stays as the advanced mode. A *persistent* rig FX slot (an always-on, keyable emitter — the other half of invisible-cinematic §12.4a) is still NOT built.
- **Live particle previews everywhere** — the effect plays not just in `/fx` (`FxStage`) but in the **Rigger** and **Symbols state machine** via the shared `fxOverlay` on their raw-WebGL stages, all now riding the bone's **full transform** (position + rotation + per-axis scale) to match the game.
- **Effect atlases auto-ship** — `exportEditorArt` walks the project's effects and ships every layer's `art.assetKey`, so a placed/bound effect's particles have textures with no extra step.

## Recent changes
- 2026-08-28 — **Per-particle Min / Max everywhere the library can express it, a colour overlay, spin accel + a rotation lock, flipbook speed/loop, and layer stack ops.** The inspector's biggest gap wasn't a missing knob, it was that a section VANISHED when its behavior was absent (`{#if alphaEnds}`) — so a layer without an alpha curve gave the author no way to add one. Every curve section now carries an **On** switch, and Alpha/Scale/Speed a **Min / Max** switch. The variation itself is the library's own model: `minMult` on `scale`/`moveSpeed` (a random multiplier in `[minMult, 1]` drawn once per particle and applied to the whole curve), so `min` writes the ratio and `max` writes the authored endpoint — and, unavoidably, **one ratio governs both ends of a curve**, which the UI says out loud rather than faking independent bands. `alpha` is the one curve the library gives no `minMult` and NOTHING randomises tint, so `engine-fx/src/behaviors.ts` adds exactly two custom behaviors — **`fxAlpha`** (the stock alpha config plus `minMult`; the two swap by TYPE alone, so variation-off configs stay 100% stock) and **`fxColorOverlay`** (a colour blended in at a per-particle intensity, running at order `Late` so it composes over `color`; it remembers the tint it last wrote, so with no colour behavior present it can't compound its own output into a runaway tint). They are import-free classes and `registerFxBehaviors(Emitter)` takes the class as an argument, keeping `engine-fx` PixiJS-free; the runtime registers in `<ParticleEmitter>` and all three launcher stages inherit it from the shared `effectEmitter.client.ts`. Also: `art.framerate`/`art.loop` (an EffectDoc schema addition — absent ⇒ the old match-life default, so every existing effect is byte-identical) threaded through `bindArt` at all four call sites; spin **accel** and a `noRotation` **angle lock** exposed; **▲▼ reorder / ⧉ duplicate / Copy-Paste-across-effects** in the Layers panel, with `FxStage` re-appending emitter containers in doc order each rebuild so a reorder actually restacks the preview (it only ever added them at creation). Verified: `engine-fx` typecheck, launcher `tsc` clean over every FX module, launcher build, and a new headless harness `tools/fx-spike/variation.ts` (`pnpm --filter fx-spike run variation`, 80 assertions) covering purity, the alpha↔fxAlpha swap, the ratio math, the two behaviors' actual particle output, `registerFxBehaviors`, flipbook binding, layer ops, and save→reopen through `normalizeEffectDoc`. All ten pre-existing fx-spike harnesses stay green. **NOT browser-verified** — `/fx` is auth + Postgres + R2 gated (open item 1). **Engine change on `main` — reaches shipped games only via a runtime-bundle republish + `engine` submodule bump.**
- 2026-08-27 — **A rig binding now carries draw depth + five modifiers, not just an effect and a bone.** `evtObj.fx` gained `slot` (draw at that slot's place in the skeleton draw order, via spine-pixi `addSlotObject`) plus `alpha` / `scale` / `delay` / `duration` / `speed`, all optional and all ABSENT by default so every rig baked before them is byte-identical. `readRigFxOverrides` in `engine-layout` is the single clamp the bake, the runtime registry and both live previews read through, and `rigFxExport.ts` now imports the binding type instead of hand-mirroring it. `duration` closes a real preview-vs-game divergence: `forceEmit` started emission and nothing ended it, so a continuous effect fired from a keyframe emitted forever in-game while the previews capped at ~1.5s. Guarded by `check:rig-fx-overrides` (mutation-verified). Detail + the owed in-game pixel check in [status/rigger](rigger.md).
- 2026-08-20 — **The Tier-B backdrop skeleton never loaded: `loadFxSpine` fetched its atlas pages with `Assets.load`.** Pixi's resolver picks a loader by the URL's apparent EXTENSION and drops the query string first, so `/spine/file?dir=…&name=….webp` reads as extension-less — the load resolves to `null` and reading `.source` off it throws, aborting the skeleton. Exactly the trap the emitters' own page loading was fixed for in July (`/api/editor/asset?key=…`), in the one place that still called `Assets.load`; it now goes through the same `loadPageSource` (fetch → `createImageBitmap` → `ImageSource`). Surfaced via the admin boot-mark preview, which reuses this helper — full story + the live verification in [launcher.md](launcher.md).
- 2026-08-03 — **Preview↔runtime FX speed mismatch fixed — the `/fx` editor now plays effects at the EXACT game speed.** The in-game runtime (`ParticleEmitter.svelte`) advanced the emitter by `deltaMS * 0.00234` (~2.34× real seconds), but the `/fx` preview (`FxStage.svelte`) used `deltaMS / 1000` (1× real seconds) — so an effect ran ~2.34× faster in-game than the editor showed, the drift behind mis-timed authored delays. Both now advance through ONE shared scalar: new `packages/engine-fx/src/playback.ts` — `DEFAULT_EMIT_SPEED = 0.00234`, `emitterDeltaSeconds(deltaMS, emitSpeed?)`, and `emitterSecondsToWallMs(emitterSeconds, emitSpeed?)` (emitter-lifetime → true wall-clock ms; `1/0.00234 ≈ 427ms` per emitter-second). All three emitter-driving renderers now call `emitterDeltaSeconds` — the runtime `ParticleEmitter.svelte`, the `/fx` `FxStage.svelte`, and the shared Rigger/Symbols `fxOverlay.client.ts`; each preview's backdrop SPINE stays on real seconds (a spine clip is wall-clock). **Effects now appear ~2.34× faster in the editor than before — that is the correct, game-matching speed, not a regression.** `emitterSecondsToWallMs` also backs Flow v2's new `showContainer.durationMs` pin (an FX node's contribution to a screen's duration). Verified: `engine-fx` typecheck clean + offline scalar math.
