# ComfyUI (cloud R&D) — status

> Design: [docs/design/runpod-comfyui-backend.md](../design/runpod-comfyui-backend.md) · Infra/runbook: [docs/INFRA.md](../INFRA.md) "ComfyUI R&D pod (RunPod)" · Guide: [docs/tools/comfyui.md](../tools/comfyui.md) · Character workflow: [docs/guides/qwen-cartoon-character-blueprint.md](../guides/qwen-cartoon-character-blueprint.md) · Agents: `.claude/agents/launcher-studio.md` (the card) + `.claude/agents/atlas-python-tools.md` (the pod/backend)

**One-line state:** `/comfyui` is a full **fleet control panel** — one row per RunPod pod (different GPU cards), each with a live status badge + Start / Open / Stop, plus admin-configured idle auto-stop. The fleet is admin-managed in `app_settings.runpodPods`; `RUNPOD_API_KEY` is the shared secret and a legacy `RUNPOD_POD_ID` is the single-pod fallback.

## Current state
- **`/comfyui` fleet control panel** (id `comfyui`, third-party name "ComfyUI") — full-page, no iframe, renders the shared `ToolTopBar`. Polls `/comfyui/status` (~5s) for live per-pod state (`probeFleet` — each pod probed concurrently, resilient to one hanging) and renders one of two shapes:
  - **Not configured** (no fleet + no `RUNPOD_API_KEY` → `podControlConfigured()` false / `data.podControl` false) → a "set `RUNPOD_API_KEY`, add pods in Admin" landing (mentions the legacy `RUNPOD_POD_ID`).
  - **Fleet control panel** → a list of pods, each row = label + status badge (**running** / **starting** / **stopped**) + a **specs line** (Cost/hr · VRAM · Processor, from `podSpecs`). Running → **Open ComfyUI ↗** (new tab, once `comfyReady`) + **Stop** (`podStop`). Starting → "Warming up ~2 min…" + **Cancel**. Stopped → **Start** (RunPod GraphQL `podResume`); a failed Start (e.g. "not enough free GPUs") shows **inline on that pod's row** with **Retry**, so the artist tries the next card.
- **Fleet model:** the effective fleet is the admin-managed `runpodPods` list (`getRunpodPods` → `getEffectiveFleet`), each entry `{id,label}`; the ComfyUI URL is **derived** from the id (`podUrl` → `https://<id>-8188.proxy.runpod.net`), never stored. Empty list → a single legacy pod synthesized from `RUNPOD_POD_ID` (URL prefers `COMFY_RND_URL`) so an existing single-pod deploy keeps working. `start`/`stop` validate the `podId` belongs to the fleet before driving the shared API key.
- **"What's installed" panel** — a collapsible section under the fleet listing the **models on the Network Volume** (per folder, expandable to filenames) and the **custom node packs** the answering pod's ComfyUI loaded. Read LIVE from a pod, never from a list in this repo, and **fallback-tolerant**: model index tried across `/api/experiment/models` → `/experiment/models` → `/api/models` → `/models`, packs across a future `/invisible/inventory` (ours) → ComfyUI-Manager → a **streamed regex scan of `/object_info`** grouped by `python_module` (streamed, not parsed — that response is 10–25 MB and this service has been OOM-killed by a big in-memory payload before). Reads once on load + on **Refresh**, 60s server cache, never polled. An always-on **volume pod** (`COMFY_VOLUME_POD_ID` / `COMFY_VOLUME_URL`, e.g. a cheap CPU pod on the same volume) makes it answer with the whole GPU fleet stopped; otherwise it falls back to any ready fleet pod. Read-only — it cannot start, stop or bill a pod.
- **Endpoints:** `status`, `start` (`{podId}`), `stop` (`{podId}`), `ping`, `inventory` under `(app)/comfyui/` (all `requireComfyAccess`). While the tab is visible it heartbeats `ping` (~60s) to keep the fleet alive; closing the tab does NOT stop a pod.
- **Admin fleet editor:** Admin → Settings → **"ComfyUI R&D pod fleet"** — add/remove pods (id + label), a live status pill per row, "Save fleet" (`?/setRunpodPods` → `runpodPods`), plus the idle config (enable + minutes) and per-pod manual Stop.
- **Idle auto-stop** — a launcher watchdog stops an idle pod after N minutes. Admin-configured (NOT env), stored in `app_settings` (`runpodIdleEnabled` / `runpodIdleMinutes`, default 20). Stopping is gated on THREE independent holds, because reclaiming a GPU drops the artist's session: (a) a **one-hour session lease** taken when "Open ComfyUI ↗" is clicked (`runpodActivity`), (b) a busy **or unreachable** ComfyUI — `comfyQueueBusy` is tri-state and `null` (unknown) counts as busy, and (c) the idle window plus `IDLE_TICKS_REQUIRED` (3) consecutive confirmations. The panel shows what's holding the pod.
- **Two operational cautions:** run only ONE pod at a time when they share a Network Volume (write conflicts otherwise); a stopped pod does NOT reserve its GPU, so a Start can fail on scarce cards — hence the fleet.
- It does NOT auto-redirect (pods are on-demand and may be stopped, so a bare redirect would dump the artist on a RunPod error page).
- Access: `admin`, `developer`, `artist` (`ROLE_TOOLS`). Placed in the **Assets** stage of the tool bar, next to the Atlas Maker.
- Purpose: an artist runs GPU-heavy ComfyUI R&D on a pod (their laptop OOMs), then exports the network as an **Atlas Maker blueprint** ([blueprints §3](../design/invisible-blueprints.md)).

## Recent changes
- 2026-08-20 — **each pod card now carries its Cost/hr, VRAM and Processor** (owner request: "inside the comfyUI cards I would like to have more specs for each card"). Until now the only thing distinguishing "RTX PRO 4500 (Blackwell)" from "Pro 6000" was an admin-typed label, so choosing a card meant knowing the fleet by heart — and the two questions that actually decide it (does the model fit in VRAM, what does an hour cost) were answerable only in RunPod's own console. `podSpecs()` reads them from the pod (`costPerHr`, `gpuCount`, `vcpuCount`, `memoryInGb`, `machine.gpuDisplayName/gpuTypeId/cpuTypeId`) and they render as a three-column line under the status badge.
  - **VRAM is not on the pod** — RunPod reports which GPU a pod has, never how much memory that card carries. It comes from a second query, the `gpuTypes` catalogue, cached 6h (static hardware data) and keyed on a normalised name (`NVIDIA GeForce RTX 4090` → `rtx4090`) so `gpuTypeId` or `gpuDisplayName` both match.
  - **Three defences, because this sits inside the 5s status poll and must never cost the fleet its status.** (a) Specs are cached per pod — 10 min when complete, 60s while still filling in — so the poll is almost always free. (b) The pod query runs in TIERS, dropping the least-certain `machine` sub-fields first: one unknown field fails a WHOLE GraphQL query, and without tiers a schema change on `cpuTypeId` would take the price and RAM down with it. (c) Reads MERGE into the last known record rather than replacing it, so a stopped pod (RunPod may return no `machine`) keeps showing the GPU it had rather than blanking. A rejected `gpuTypes` query is negative-cached for 10 min so it isn't re-sent per pod per refresh.
  - **Not verified against the live RunPod API** — the key lives on the launcher service, not on disk here. What is verified: lint clean, the page compiles, and every failure path degrades to a missing line rather than a wrong figure or a broken card. The specific unknowns are whether `machine.cpuTypeId`/`gpuTypeId` exist on `PodMachineInfo` (tier 2/3 covers it — Processor then falls back to "N vCPU · N GB RAM") and whether a *stopped* pod reports `machine` at all. **Confirm on the next visit to `/comfyui`: all three lines should be populated on at least one card.**
- 2026-08-20 — **the PuLID-Flux2 build shipped a broken `ml_dtypes`, and the fix is dependency FLOORS on the face stack.** Caught by reading the build log of the very image that had just gone green, not by anything failing. `ComfyUI-PuLID-Flux2/requirements.txt` pins `ml_dtypes==0.3.2` and `numpy<2.0.0`; the `for r in */requirements.txt` loop applies each node's file with `|| true`, so both were honoured silently — **ml_dtypes 0.6.0 → 0.3.2** and **onnx 1.22.0 → 1.19.0**. numpy recovered by accident (the cu128 torch step reinstalls 2.4.6 last), and that accident is what turned a stale pin into a defect: **ml_dtypes 0.3.2 is a Jan-2024 C extension built against the numpy 1.x array API, so under numpy 2 it fails to import** — verified directly, `AttributeError: _ARRAY_API not found` / `ImportError: numpy.core._multiarray_umath failed to import`. onnx declares `ml_dtypes` as a hard dependency and insightface imports onnx, so this put the **whole face stack** at risk, including the FLUX.1 `ComfyUI-PuLID-Flux` path that was verified working the day before. Fix: the explicit face-stack step (which runs *after* the loop) now carries **floors** — `ml_dtypes>=0.5.4`, `onnx>=1.22` — raising what a node dragged down without pinning a version the loop would fight over on the next rebuild.
  - **The `|| true` on that loop is the real hazard, and it now has a guard.** It exists so one node's unresolvable requirements can't fail the whole image, but the cost is that dependency damage is invisible in a green build. Floors patch one instance; the general fix ships alongside them as two checks after the last pip step — `pip check` (metadata conflicts, **advisory**, since the opencv overlap would otherwise block every build) and **`/verify-deps.py` (imports, and it FAILS the build)**. The second is the one that matters: **`pip check` would NOT have caught this bug**, because onnx declares `ml_dtypes` with no version bound, so 0.3.2 resolved clean and only fell over at import. `verify-deps.py` is baked into the image, so a pod can re-run it after a hand install or a ComfyUI-Manager node: `python /verify-deps.py`.
  - **`ghcr.io/…/atlas-comfy-pod:latest` built at 2026-08-20T11:54Z is the bad image** — do not deploy it. The rebuild from this change supersedes it.
  - opencv is also left mixed by the same loop (`opencv-python` 4.11.0.86 alongside `opencv-python-headless` / `opencv-contrib-python` 5.0.0.93, all sharing the `cv2` namespace). Not addressed here and not proven harmful — noted so the next person reading a cv2 oddity starts here.

Net result, measured on a live pod: `8188 → 404`, `8189 → 502`, ComfyUI running fine and reachable by **no route the launcher knew about**. - 2026-08-19 — **the idle watchdog was stopping pods mid-session; three holds added.** Reported as "ComfyUI keeps disconnecting, I can't finish processing my network". Two independent defects, both of which reclaimed a GPU out from under an artist:
  - **`comfyQueueBusy` reported "couldn't reach ComfyUI" as "queue empty"** (`runpod.ts`). Every failure path — non-2xx, unparseable body, network error, the 6s timeout — returned `false`, which the watchdog read as idle. ComfyUI serves `/queue` from the same process that runs the graph, so it goes silent exactly while loading a checkpoint or decoding, i.e. when the pod is busiest.
