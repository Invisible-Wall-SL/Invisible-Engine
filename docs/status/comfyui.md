# ComfyUI (cloud R&D) — status

> Design: [docs/design/runpod-comfyui-backend.md](../design/runpod-comfyui-backend.md) · Infra/runbook: [docs/INFRA.md](../INFRA.md) "ComfyUI R&D pod (RunPod)" · Guide: [docs/tools/comfyui.md](../tools/comfyui.md) · Character workflow: [docs/guides/qwen-cartoon-character-blueprint.md](../guides/qwen-cartoon-character-blueprint.md) · Agents: `.claude/agents/launcher-studio.md` (the card) + `.claude/agents/atlas-python-tools.md` (the pod/backend)

**One-line state:** `/comfyui` is a full **fleet control panel** — one row per RunPod pod (different GPU cards), each with a live status badge + Start / Open / Stop, plus admin-configured idle auto-stop. The fleet is admin-managed in `app_settings.runpodPods`; `RUNPOD_API_KEY` is the shared secret and a legacy `RUNPOD_POD_ID` is the single-pod fallback.

## Current state
- **`/comfyui` fleet control panel** (id `comfyui`, third-party name "ComfyUI") — full-page, no iframe, renders the shared `ToolTopBar`. Polls `/comfyui/status` (~5s) for live per-pod state (`probeFleet` — each pod probed concurrently, resilient to one hanging) and renders one of two shapes:
  - **Not configured** (no fleet + no `RUNPOD_API_KEY` → `podControlConfigured()` false / `data.podControl` false) → a "set `RUNPOD_API_KEY`, add pods in Admin" landing (mentions the legacy `RUNPOD_POD_ID`).
  - **Fleet control panel** → a list of pods, each row = label + status badge (**running** / **starting** / **stopped**). Running → **Open ComfyUI ↗** (new tab, once `comfyReady`) + **Stop** (`podStop`). Starting → "Warming up ~2 min…" + **Cancel**. Stopped → **Start** (RunPod GraphQL `podResume`); a failed Start (e.g. "not enough free GPUs") shows **inline on that pod's row** with **Retry**, so the artist tries the next card.
- **Fleet model:** the effective fleet is the admin-managed `runpodPods` list (`getRunpodPods` → `getEffectiveFleet`), each entry `{id,label}`; the ComfyUI URL is **derived** from the id (`podUrl` → `https://<id>-8188.proxy.runpod.net`), never stored. Empty list → a single legacy pod synthesized from `RUNPOD_POD_ID` (URL prefers `COMFY_RND_URL`) so an existing single-pod deploy keeps working. `start`/`stop` validate the `podId` belongs to the fleet before driving the shared API key.
- **Endpoints:** `status`, `start` (`{podId}`), `stop` (`{podId}`), `ping` under `(app)/comfyui/` (all `requireComfyAccess`). While the tab is visible it heartbeats `ping` (~60s) to keep the fleet alive; closing the tab does NOT stop a pod.
- **Admin fleet editor:** Admin → Settings → **"ComfyUI R&D pod fleet"** — add/remove pods (id + label), a live status pill per row, "Save fleet" (`?/setRunpodPods` → `runpodPods`), plus the idle config (enable + minutes) and per-pod manual Stop.
- **Idle auto-stop** — a launcher watchdog stops an idle pod after N minutes. Admin-configured (NOT env), stored in `app_settings` (`runpodIdleEnabled` / `runpodIdleMinutes`, default 20). Stopping is gated on THREE independent holds, because reclaiming a GPU drops the artist's session: (a) a **one-hour session lease** taken when "Open ComfyUI ↗" is clicked (`runpodActivity`), (b) a busy **or unreachable** ComfyUI — `comfyQueueBusy` is tri-state and `null` (unknown) counts as busy, and (c) the idle window plus `IDLE_TICKS_REQUIRED` (3) consecutive confirmations. The panel shows what's holding the pod.
- **Two operational cautions:** run only ONE pod at a time when they share a Network Volume (write conflicts otherwise); a stopped pod does NOT reserve its GPU, so a Start can fail on scarce cards — hence the fleet.
- It does NOT auto-redirect (pods are on-demand and may be stopped, so a bare redirect would dump the artist on a RunPod error page).
- Access: `admin`, `developer`, `artist` (`ROLE_TOOLS`). Placed in the **Assets** stage of the tool bar, next to the Atlas Maker.
- Purpose: an artist runs GPU-heavy ComfyUI R&D on a pod (their laptop OOMs), then exports the network as an **Atlas Maker blueprint** ([blueprints §3](../design/invisible-blueprints.md)).

Force a node error (e.g. an OOM), kill the socket mid-run, reconnect, and confirm the node lights up. If the frontend has moved under us the extension degrades to a console line rather than throwing — so a silent failure looks like "nothing happened", not a crash.
2. **Live-verify the control panel** end-to-end: as an artist → `/comfyui` → Start → wait for ready → Open → Stop; and confirm idle auto-stop reclaims the GPU after the admin-set window with an empty queue.

Render one SDXL and one FLUX blueprint, then `node scripts/comfy-last-error.mjs <podUrl>`. The remaining risk is the baked blueprints in `services/atlas-tool/blueprints_src/` — api-prompt graphs keyed on node class + input NAMES, which fail at **submit** time, not build time — and `ComfyUI-Invisible-ErrorRecall` against the newer frontend (open item 1). Note the serverless worker image was **already promoted** in the same merge (owner's call, made knowingly), so prod is on v0.33.1 from its next cold worker; a break there shows up intermittently as warm workers cycle, and the fix is redeploying the endpoint on the previous image digest.
4. **There is still no render smoke test in CI.** `test_blueprint_models.py` covers only the Manager model-install queue, so nothing mechanically catches a blueprint that a core/node bump invalidated — the gap that made this bump a manual, hardware-gated verification. Worth building regardless of the bump.
5. **Watch for FLUX 3 [dev] open weights — nothing to do until they land.** BFL announced **FLUX 3** on 2026-07-23 (one multimodal model over image/video/audio/action-prediction), but it is **playground + API only**: no `black-forest-labs/FLUX.3*` repo on Hugging Face, no `flux3` in ComfyUI core, and an open-weight `[dev]` release confirmed in the launch plan with **no date, no licence, and no parameter count**. Two things decide whether it is ever relevant here: (a) **the licence** — FLUX.2 split cleanly into klein (apache-2.0, shippable) and dev (non-commercial, R&D-only), and a non-commercial FLUX 3 [dev] lands in the same dead end as FLUX.1-dev/PuLID; (b) **size** — FLUX.2 [dev] at 32B already exceeded every card in the fleet, and a multimodal successor will not be smaller. Video/audio/action are off our path entirely (slot art → Spine), so image quality is the only reason to care. When weights do land, adding it is one `MODEL_SETS` entry in `fetch-models.py`.
6. **Node/model parity** — a custom node or model used in R&D must also exist on the Atlas Maker's generation backend (custom nodes are baked into the serverless worker image; models live on the volume + mirrored to R2) or the resulting blueprint won't run. Tighten this workflow so an R&D blueprint reliably runs in the Atlas Maker afterward.

## Recent changes
- 2026-08-19 — **the documented `curl … raw.githubusercontent.com` provisioning step never worked: the repo is PRIVATE.** Hit while fetching `fetch-models.py` onto a pod; `provision.sh` carries the identical instruction, so that step has been broken for as long as it has been written down. GitHub answers **404, not 401**, for a private repo, so it reads as "the file is missing" when the file is plainly on `main` — which is exactly why it survived unnoticed. README now leads with the constraint and gives the two methods that actually work: **paste** (`gzip -9c … | base64 -w0` on your machine → `base64 -d | gunzip` on the pod — no credentials on the pod at all) or a **fine-grained read-only PAT**. Paste is preferred on a shared pod: a token in the shell history of a machine several people reach is a credential leak, and that token can read the whole repo.
  - **Worth doing properly: bake `fetch-models.py` into the pod image** so no pod ever has to fetch it. Not done here because the image build context is `services/atlas-comfy-pod/` and Docker `COPY` cannot escape it — so it means either duplicating the file (the `ComfyUI-PuLID-Flux` compromise) or moving the build context to the repo root and rewriting every `COPY` path. The image was verified working hours earlier; churning its build to save a paste was not the trade to make in the same session.
- 2026-08-19 — **`/comfyui` links direct to the pod when TCP 8188 is exposed; copies the URL when it isn't.** The follow-up to the cross-site 403 below: the proxy cannot be linked to from a page at all, so the card now prefers a **direct `http://<ip>:<publicPort>`** that skips the proxy — which also retires the `/ws` drop on long renders that INFRA has told artists to expose TCP for. `podStatus` became `podProbe`, returning status + `directUrl` from the SAME GraphQL call (the fleet polls every ~5s; a second call per pod would double that for a field already in the `runtime` object). `directUrlFromPorts` only accepts a TCP-typed, public, `privatePort: 8188` entry with both an ip and a public port — RunPod assigns that external port at each resume and it **changes every start**, so it is read live, never cached, and never derived from the pod id. When there's no TCP port the button becomes **"Copy ComfyUI URL"** with a one-line explanation, so the tool stops handing out a link it knows will 403.
  - **The `ports` field is requested best-effort with a fallback to the old minimal query.** If RunPod's schema ever drops or renames it the whole query would fail, every pod would read `'unknown'`, and a *running* pod would render a "Start" button — a worse regression than the bug being fixed. Status matters more than the convenience link.
  - Verified: `tsc --noEmit` clean, launcher build green, and `directUrlFromPorts` exercised over 14 cases (http-typed ports as our pods have today, non-public tcp, wrong private port, missing ip/port, `publicPort: 0`, null entries, a stopped pod's null runtime, picking 8188 out of several). **Not verified live** — the panel needs a logged-in launcher plus `RUNPOD_API_KEY`, and no pod has TCP 8188 exposed yet, so the `directUrl` branch has never rendered against the real API. The `ports` schema itself is inferred from RunPod's docs, not observed; the fallback exists precisely because of that.
- 2026-08-19 — **"Access denied" clicking a pod link from a tool = RunPod's cross-site rule, not our pod.** Reported as *"why do I get this error from the Pipeline, but I can open the link by itself?"* — Chrome's 403 page on `<podId>-8188.proxy.runpod.net`. RunPod's proxy rejects any browser request carrying **`Sec-Fetch-Site: cross-site`**, which the browser stamps from the *initiator* origin: a click from `app.invisiblewall.org` gets it, an address-bar navigation (`none`) does not. **Not an iframe problem** — a `same-origin` iframe returns 200, so the destination is irrelevant and `/comfyui` (correctly full-page) needs no change; the first read of this blamed framing and was wrong. The 403 is a bare `Content-Length: 0` from `Server: cloudflare` with no block page and no `cf-mitigated`, i.e. RunPod's own anti-hotlink edge rule rather than a CF WAF challenge, so no UA/Referer tweak defeats it. **Server-side calls are unaffected** (curl / undici / node / no-UA all 200), so generation never broke — but the same Cloudflare front still 403s `User-Agent: Python-urllib/*`, the repo's oldest ComfyUI trap, so a call site that skips `iw_common.comfy.cf_headers()` would fail here too. Workaround today is a fresh tab; full evidence table + options in [docs/INFRA.md](../INFRA.md) §"Access to …proxy.runpod.net was denied". **Unconfirmed whether this is new RunPod behaviour** — no older pod was running to compare against.

- 2026-08-19 — **the error now finds you: `ComfyUI-Invisible-ErrorRecall` baked into the R&D pod image.** `scripts/comfy-last-error.mjs` (below) worked but had to be remembered and run by hand. This is the same `/history` read as a ComfyUI **frontend extension**, so it fires by itself: on `reconnected` it surfaces the missed error modally, on page load it toasts + highlights without interrupting. Node highlighting goes through `app.lastNodeErrors` — the transient channel ComfyUI uses for `/prompt` validation errors — so **the graph is never mutated** and nothing can be saved into an artist's workflow; every frontend API is feature-detected (the frontend bundle is the fastest-moving part of ComfyUI, and a debugging aid that throws is worse than one that quietly does less); an error seen live is not replayed. Ships no nodes and no Python deps. Verified across 16 scenarios against stubbed `app`/`api` — dedupe, live-seen suppression, clean history, a fetch that throws while still disconnected, a stripped frontend with neither toast nor dialog, and a node deleted from the graph. **Still owner-verify-owed on a live pod** (see open items) — a pod picks it up only after the image rebuilds AND that pod is redeployed; to test on a running pod, copy the folder to `/ComfyUI/custom_nodes/` and restart ComfyUI.
- 2026-08-19 — **`scripts/comfy-last-error.mjs`** — reads the failing node + real error back out of a pod's `/history`, so it survives the dropped WebSocket that hides it in the UI (ComfyUI delivers `execution_error` over `/ws` only). Prints node id / class / **canvas title** / exception / that node's inputs / what feeds it / traceback. Its three outcomes separate a graph error from a transport drop from a process death. Runbook + the disconnect causes to rule out first (Spot pod, proxy WS timeout, VRAM) are in [docs/INFRA.md](../INFRA.md) §"Debugging \"ComfyUI disconnected\" on a pod".
- 2026-08-19 — **the idle watchdog was stopping pods mid-session; three holds added.** Reported as "ComfyUI keeps disconnecting, I can't finish processing my network". Two independent defects, both of which reclaimed a GPU out from under an artist:
  - **`comfyQueueBusy` reported "couldn't reach ComfyUI" as "queue empty"** (`runpod.ts`). Every failure path — non-2xx, unparseable body, network error, the 6s timeout — returned `false`, which the watchdog read as idle. ComfyUI serves `/queue` from the same process that runs the graph, so it goes silent exactly while loading a checkpoint or decoding, i.e. when the pod is busiest. Now **tri-state** (`true` / `false` / `null` = unknown), timeout raised 6s → 15s, and the watchdog treats unknown as busy. Only a parsed, confirmed-empty queue is idle.
  - **The heartbeat goes silent the moment the pod is used.** `/comfyui`'s ping is gated on `document.visibilityState === 'visible'`, but "Open ComfyUI ↗" sends the artist to a *different* tab — so `lastActivity` froze at the click, and after the idle window the only thing left holding the pod was a busy queue. That says nothing while a network is being **built**, so a >20-min build session was stopped mid-flight. Fixed with a **one-hour session lease** (`runpodActivity`: `grantLease`/`leaseActive`/`clearLease`, granted by `POST /comfyui/ping {lease:true}` on the Open click, dropped on an explicit Stop). The watchdog also bumps the clock while a lease is held, so the idle countdown starts when the lease **expires**, not when it was granted.
  - Also added a **3-consecutive-tick debounce** before any stop, so no single sample can reclaim a pod; and factored the panel payload into `fleetPayload()` (`runpod.ts`) — `status`/`start`/`stop` each hand-built the same object, which is why a new field reached only one of them.
  - Verified by driving the real `tick()` with a stubbed fleet (12 scenarios: lease holds, unknown-never-stops, busy-never-stops, in-window, the 3-tick debounce and its reset, disabled, post-lease countdown) and the real `comfyQueueBusy` against a stand-in ComfyUI (503 / garbage / refused / unresponsive → all `null`). No test runner exists in `launcher-api`, so these ran as throwaway harnesses rather than committed tests — **worth revisiting: this area has no regression net.**
