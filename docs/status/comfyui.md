# ComfyUI (cloud R&D) — status

> Design: [docs/design/runpod-comfyui-backend.md](../design/runpod-comfyui-backend.md) · Node-manager plan: [docs/design/comfyui-node-manager.md](../design/comfyui-node-manager.md) · Infra/runbook: [docs/INFRA.md](../INFRA.md) "ComfyUI R&D pod (RunPod)" · Guide: [docs/tools/comfyui.md](../tools/comfyui.md) · Character workflow: [docs/guides/qwen-cartoon-character-blueprint.md](../guides/qwen-cartoon-character-blueprint.md) · Agents: `.claude/agents/launcher-studio.md` (the card) + `.claude/agents/atlas-python-tools.md` (the pod/backend)

**One-line state:** `/comfyui` is a full **fleet control panel** — one row per RunPod pod (different GPU cards), each with a live status badge + Start / Open / Stop, plus admin-configured idle auto-stop. The fleet is admin-managed in `app_settings.runpodPods`; `RUNPOD_API_KEY` is the shared secret and a legacy `RUNPOD_POD_ID` is the single-pod fallback.

## Current state
- **`/comfyui` fleet control panel** (id `comfyui`, third-party name "ComfyUI") — full-page, no iframe, renders the shared `ToolTopBar`. Polls `/comfyui/status` (~5s) for live per-pod state (`probeFleet` — each pod probed concurrently, resilient to one hanging) and renders one of two shapes:
  - **Not configured** (no fleet + no `RUNPOD_API_KEY` → `podControlConfigured()` false / `data.podControl` false) → a "set `RUNPOD_API_KEY`, add pods in Admin" landing (mentions the legacy `RUNPOD_POD_ID`).
  - **Fleet control panel** → a list of pods, each row = label + status badge (**running** / **starting** / **stopped**) + a **specs line** (Cost/hr · VRAM · Processor, from `podSpecs`). Running → **Open ComfyUI ↗** (new tab, once `comfyReady`) + **Stop** (`podStop`). Starting → "Warming up ~2 min…" + **Cancel**. Stopped → **Start** (RunPod GraphQL `podResume`); a failed Start (e.g. "not enough free GPUs") shows **inline on that pod's row** with **Retry**, so the artist tries the next card. A stopped row also carries a **GPU availability badge** — **GPU available** or **no GPUs free** — when RunPod gives a definite answer (`podAvailability` reads `myself.datacenters.gpuAvailability`, ONE query for the whole fleet, cached 60s, scoped to the pod's data centre), so the dry card is visible before the click rather than after it. No definite answer renders NO badge, deliberately.
- **Fleet model:** the effective fleet is the admin-managed `runpodPods` list (`getRunpodPods` → `getEffectiveFleet`), each entry `{id,label}`; the ComfyUI URL is **derived** from the id (`podUrl` → `https://<id>-8188.proxy.runpod.net`), never stored. Empty list → a single legacy pod synthesized from `RUNPOD_POD_ID` (URL prefers `COMFY_RND_URL`) so an existing single-pod deploy keeps working. `start`/`stop` validate the `podId` belongs to the fleet before driving the shared API key.
- **"What's installed" panel** — a collapsible section under the fleet listing the **models on the Network Volume** (per folder, expandable to filenames) and the **custom node packs** the answering pod's ComfyUI loaded. Read LIVE from a pod, never from a list in this repo, and **fallback-tolerant**: model index tried across `/api/experiment/models` → `/experiment/models` → `/api/models` → `/models`, packs across a future `/invisible/inventory` (ours) → ComfyUI-Manager → a **streamed regex scan of `/object_info`** grouped by `python_module` (streamed, not parsed — that response is 10–25 MB and this service has been OOM-killed by a big in-memory payload before). Reads once on load + on **Refresh**, 60s server cache, never polled. An always-on **volume pod** (`COMFY_VOLUME_POD_ID` / `COMFY_VOLUME_URL`, e.g. a cheap CPU pod on the same volume) makes it answer with the whole GPU fleet stopped; otherwise it falls back to any ready fleet pod. Read-only — it cannot start, stop or bill a pod.
- **Endpoints:** `status`, `start` (`{podId}`), `stop` (`{podId}`), `ping`, `inventory` under `(app)/comfyui/` (all `requireComfyAccess`). While the tab is visible it heartbeats `ping` (~60s) to keep the fleet alive; closing the tab does NOT stop a pod.
- **Admin fleet editor:** Admin → Settings → **"ComfyUI R&D pod fleet"** — add/remove pods (id + label), a live status pill per row, "Save fleet" (`?/setRunpodPods` → `runpodPods`), plus the idle config (enable + minutes) and per-pod manual Stop.
- **Idle auto-stop** — a launcher watchdog stops an idle pod after N minutes. Admin-configured (NOT env), stored in `app_settings` (`runpodIdleEnabled` / `runpodIdleMinutes`, default 20). Stopping is gated on THREE independent holds, because reclaiming a GPU drops the artist's session: (a) a **one-hour session lease** taken when "Open ComfyUI ↗" is clicked (`runpodActivity`), (b) a busy **or unreachable** ComfyUI — `comfyQueueBusy` is tri-state and `null` (unknown) counts as busy, and (c) the idle window plus `IDLE_TICKS_REQUIRED` (3) consecutive confirmations. The panel shows what's holding the pod.
- **Two operational cautions:** run only ONE pod at a time when they share a Network Volume (write conflicts otherwise); a stopped pod does NOT reserve its GPU, so a Start can fail on scarce cards — hence the fleet.
- It does NOT auto-redirect (pods are on-demand and may be stopped, so a bare redirect would dump the artist on a RunPod error page).
- Access: `admin`, `developer`, `artist` (`ROLE_TOOLS`). Placed in the **Assets** stage of the tool bar, next to the Atlas Maker.
- Purpose: an artist runs GPU-heavy ComfyUI R&D on a pod (their laptop OOMs), then exports the network as an **Atlas Maker blueprint** ([blueprints §3](../design/invisible-blueprints.md)).

## Recent changes
- 2026-09-10 — **Florence-2 runs: the native loader needed the image token NAMED.** The loader branch from 4d8ddd10 was right and did take the native path, but then died on `RobertaTokenizer has no attribute image_token` (transformers **5.16.1** on the pod — note that is not the 5.8.0 on the dev box, so local checks are not representative). Cause: `microsoft/Florence-2-*` predates transformers' first-party Florence-2 and ships no `processor_config.json` / `special_tokens_map.json` (both 404 on the Hub), so its tokenizer loads as a plain RobertaTokenizer and `Florence2Processor.__init__` cannot find `image_token`. **Reproduced in an isolated venv pinned to 5.16.1 before changing anything** — the third time this analyzer was diagnosed by inference, and the first time it was diagnosed by reproduction. Fix: pass `extra_special_tokens={'image_token': '<image>'}`, tried only AFTER a plain load fails, so a properly converted repo keeps whatever token IT declares. Verified this is a real fix and not merely non-throwing: `<image>` resolves to **vocab id 50265**, not `<unk>` (3), and the processor then emits the **577** image placeholders the vision tower expects with `pixel_values (1, 3, 768, 768)` across all three caption tasks. 61 tests.
- 2026-09-10 — **`Semantic Layer Analyze` now defaults to the `florence2` analyzer, because the old default quietly reintroduced the thing the extension exists to remove.** `captions` keyed by index is an assertion about a SLOT: swap two layers and it describes the wrong one. The owner hit this immediately — "I am basically hardcoding my layers, and the detection needs to work" — and was right. Order-independence holds for everything downstream of the description, but the description itself has to come from the CONTENT, and only a pixel-reading backend does that. `captions` stays for the case where a captioner node is already in the graph, and the README now says to key it by `layer_id` (a content hash) rather than by index. The shipped example workflows switch to `florence2` and set `composite_layer: first`, which is the Qwen-correct setting nobody could have known before the first real run. **The tooltip discloses the ~0.5 GB first-run download** — that cost is the reason the default was not flipped earlier, and it is worth paying for detection that actually works. 57 tests; the default is pinned by one so a future edit cannot drift it back to a text backend.
- 2026-09-07 — **First real Qwen decomposition ran, and it broke three assumptions at once (open item 13 closed).** A pirate-on-a-raft picture through `image → layers → semantic` on pod `rhg3ujzkcahn2q`:
  - **The extra plane is the composite, and it is index 0.** `layers=3` returns `[0] composite · [1] water · [2] raft · [3] pirate`. The normalizer deliberately assumed nothing about ordering, which was right — but it means index-keyed captions silently shift by one until `composite_layer: first` is set.
  - **Qwen clears a layer to a flat MID-TONE, not to black.** `alpha_mode: auto` only knew black/white keying, so it honestly reported "no coverage" — and a layer with no coverage measures as full-frame, which flattens area, centroid and prominence, the three signals the subject resolver leans on hardest. Added **`border_key`**: median colour of the 1-px frame, keyed on RGB distance from it, threshold adapting to how noisy that flat is (`tolerance + 2·spread`). `auto` falls through to it when the border is uniform but not black/white. A genuinely varied border still returns None — declining to guess stays the behaviour for a layer that really does fill the frame.
  - **The taxonomy could not classify a boat.** `raft` matched no rule, so the raft — most of the picture — fell to UNRESOLVED at 0%. This is the class of gap no synthetic test finds, because the fixtures and the keyword list were written by the same person. Added the nautical vocabulary; **50 tests** now, including this scene.
  - **Florence-2 was NOT incompatible — the adapter picked the wrong loader.** It failed with `'Florence2LanguageConfig' object has no attribute 'forced_bos_token_id'`, which came from the MODEL REPO's own modeling code, pulled in because the adapter loaded via `AutoModelForCausalLM` + `trust_remote_code` unconditionally. **transformers >= 4.51 ships Florence-2 natively** (5.8.0 here exposes `transformers.Florence2ForConditionalGeneration`), and `comfyui-rmbg` already branches on exactly that boundary — we didn't. Fixed by branching the same way, with the version compared NUMERICALLY: `"4.9.0"` sorts after `"4.51.0"` as a string, which would pick the wrong loader on the very versions the split exists for. Do NOT pin transformers backwards for Florence-2 — that drags every other custom node with it, and it was never the problem.
  - **Escape hatch worth knowing:** the taxonomy is a `taxonomy_path` widget, so keyword fixes need only a YAML on `/workspace` — no image rebuild. Code fixes still need the image.

- 2026-09-07 — **New in-repo node pack: `ComfyUI-SemanticLayers`** (`services/atlas-comfy-pod/custom_nodes/`, baked into the pod image alongside ErrorRecall). It turns a layer-decomposition model's output into a fixed semantic interface — `BACKGROUND` / `MAIN_CHARACTER` / `SECONDARY_CHARACTERS` / `ASSETS` / `ENVIRONMENT` / `EFFECTS` / `OTHER` — so a downstream graph never depends on how many layers came back or in what order. Eight nodes under the `semantic layers` category; taxonomy + keyword rules live in `configs/default_taxonomy.yaml`, never in Python; no pip deps (torch/PyYAML/numpy/Pillow already ship, and the optional Florence-2 analyzer imports `transformers` lazily).
  - **What forced the design, verified against the local install rather than assumed:** there is no third-party "Qwen Image Layered" node — support is in ComfyUI **core** (`comfy_extras/nodes_qwen.py`, `EmptyQwenImageLayeredLatentImage`, the only layered node among the 1139 the local server reports). It emits a 5-D latent `[B, 16, layers+1, H/8, W/8]`, and the official template folds the layer axis into the batch with `LatentCutToBatch(dim="t")` before a single `VAEDecode`. So layers arrive as **one IMAGE batch of `layers+1` RGB frames — no alpha, no masks, no metadata, and no ordering contract**. Two traps worth knowing: `comfy/sd.py:984` silently decodes **plane 0 only** if you skip `LatentCutToBatch`, and nothing in `comfy/` ever sets a VAE's `output_channels` to 4, so there is no RGBA path to hope for.

Loading was verified by replicating `nodes.load_custom_node`'s exact import mechanics; `pyproject.toml` parses through `comfy_config`.
  - **Not yet proven:** it has never seen real Qwen-Image-Layered output — `qwen_image_layered_bf16` / `_vae` / `qwen_2.5_vl_7b` are **not** in `Shared\Models`, so every test drives synthetic layers (see open item 13).

- 2026-08-19 — **the idle watchdog was stopping pods mid-session; three holds added.** Reported as "ComfyUI keeps disconnecting, I can't finish processing my network". Two independent defects, both of which reclaimed a GPU out from under an artist:
  - **`comfyQueueBusy` reported "couldn't reach ComfyUI" as "queue empty"** (`runpod.ts`). Every failure path — non-2xx, unparseable body, network error, the 6s timeout — returned `false`, which the watchdog read as idle. ComfyUI serves `/queue` from the same process that runs the graph, so it goes silent exactly while loading a checkpoint or decoding, i.e. when the pod is busiest. Now **tri-state** (`true` / `false` / `null` = unknown), timeout raised 6s → 15s, and the watchdog treats unknown as busy. Only a parsed, confirmed-empty queue is idle.
  - **The heartbeat goes silent the moment the pod is used.** `/comfyui`'s ping is gated on `document.visibilityState === 'visible'`, but "Open ComfyUI ↗" sends the artist to a *different* tab — so `lastActivity` froze at the click, and after the idle window the only thing left holding the pod was a busy queue. That says nothing while a network is being **built**, so a >20-min build session was stopped mid-flight. Fixed with a **one-hour session lease** (`runpodActivity`: `grantLease`/`leaseActive`/`clearLease`, granted by `POST /comfyui/ping {lease:true}` on the Open click, dropped on an explicit Stop). The watchdog also bumps the clock while a lease is held, so the idle countdown starts when the lease **expires**, not when it was granted.
  - Also added a **3-consecutive-tick debounce** before any stop, so no single sample can reclaim a pod; and factored the panel payload into `fleetPayload()` (`runpod.ts`) — `status`/`start`/`stop` each hand-built the same object, which is why a new field reached only one of them.
  - Verified by driving the real `tick()` with a stubbed fleet (12 scenarios: lease holds, unknown-never-stops, busy-never-stops, in-window, the 3-tick debounce and its reset, disabled, post-lease countdown) and the real `comfyQueueBusy` against a stand-in ComfyUI (503 / garbage / refused / unresponsive → all `null`). No test runner exists in `launcher-api`, so these ran as throwaway harnesses rather than committed tests — **worth revisiting: this area has no regression net.**
