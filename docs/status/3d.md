**One-line state:** Phase 0a (size isolation) done — the four released runtimes stay byte-identical
with `three` in the workspace and the `arcade3d` seam present; `arcade3d` boots with a toon cube
under the HUD. Phases 0b (iOS determinism) and 0c (Blender toolchain) are their own sessions.

## Current state

- **Byte isolation (PR 1, #1707).** `IE_REPRODUCIBLE=1` pins what made two builds of one commit
  differ (`__IE_BUILD__` `builtAt` / `sha` / `engineSha` / `gameSha` / `lockfileSha256`, SvelteKit's
  `kit.version.name`). `pnpm check:runtime-bytes` compares every file under `_app/immutable/` +
  `index.html` of every runtime with `scripts/runtime-bytes/<id>.json`; the `runtime-bytes` workflow
  runs it on any change under `apps/lines/`, `packages/` or the lockfile. A push release builds the
  reproducible twin first and ends "unchanged" without moving a pointer whose release recorded the
  same whole-build hash. Detail: [engine status](engine.md) "Recent changes" 2026-11-17.
- **The seam (PR 2, #1712).** `packages/engine-3d` (`three@0.181.2`,
  `mountWorld3d(host, opts) → { sync, resize, destroy }`) draws one toon-shaded spinning cube in its own fixed canvas, inserted before
  the Pixi canvas and blind to the pointer. `families/arcade3d.ts` re-exports the arcade seam with
  `ArcadeStage3D.svelte`, which renders the stock `<ArcadeStage>`, makes the Pixi background
  transparent, and `import('engine-3d')`s the world, synced from the Pixi ticker. `config-vite`
  resolves `families/arcade` to it only under `PUBLIC_IE_3D=1` (`compiled3d`, which throws without
  arcade). Fifth row `arcade3d` (`release: 'dispatch'`) in `constants-shared/runtimes.ts`; a push
  releases `PUSH_RELEASED_IDS` (the four); release and rollback offer `arcade3d`;
  `check-family-runtime.mjs` requires the 3D markers in `arcade3d` and forbids them elsewhere.

### Phase 1b — simulation and online (2026-11-17)

- **`motion3d` for gameplay** (new exports): `zonesAt3d`, `createTracker3d` / `trackStep3d` —
  edge signals `jumped` `doubleJumped` `landed` `bounced` `leaveZone` `enterZone` (`{ zone, kind }`)
  `fell` (the death plane, once per fall). Replay `d3eac484` unchanged; the spike page rebuilt.
- **`online3d.js`** (not in `index.ts`; `engine-mechanics/src/online3d.js`): `Input3d`
  `{ seq, moveX, moveZ, buttons, yaw, pitch, view }` + `sanitizeInput3d` (exact, idempotent);
  `stepPlayer3d`; `respawnOnFall3d`; `ANIM3D` / `animBits3d`; device helpers `moveFromStick`,
  `yawFromRadians`, `radiansOfYaw` (trig before quantising, never in the step);
  `createPredictor3d` (whole-body history), `createInterpolator3d` (x/y/z lerp, yaw the short way,
  `anim`), `createSnapshotClock` re-exported; `createBot3d` / `botInput3d` (a `behaviours.js` brain
  on the x/z plane, server-only); `world3dOf` / `motionFor3d` for the config.
- **The config switch is `arcade.world3d`** (`{ level: { colliders, zones, cellSize?, killY? },
  motion?, characters?: { <id>: motion }, spawns? }`), read from the RAW doc by the server's
  `configSource` (`ServedGame.world3d`): `game-config` drops it, so no runtime's bytes change. The
  rest of the game is the ordinary `arcade.online` block (rates, seats, characters, bots).
- **The room:** `services/game-server` `roomSim3d.ts` + `arcadeRoom3d.ts`, room name `arcade3d`
  (`ROOM_NAME_3D`), schema `Input3D` / `Player3D` (`x y z` float32, `yaw` uint16, `status`, `team`,
  `anim`, `ack`, name, character, connected, bot) / `RoomState3D` (`phase`, `step`, `seed`). The 2D
  room refuses a `world3d` game and the 3D room any other; the 2D classes are untouched. Teams
  balance by BOTY's rule; one-shots are `ONLINE_EVENT` messages.
- **The fold rule:** a 3D player is stepped ONLY by an input (no step without one: a stall or a
  drop freezes it, mid-air included), and the death-plane respawn is part of the fold. So the
  device's prediction equals the room to the bit under any latency — 0 corrections measured.
- **Gate `pnpm check:room-sim-3d`** (11 checks, ~15 s): 6000 steps × 2 devices through a jittery,
  stalling link — 12 400 room/fold hash comparisons equal, 0 corrections, 24 respawns, 149 jumps,
  19 bounces, 498 ramp steps; clamp; drop/rejoin; seats/teams; bots chase and replay by seed;
  interpolator; stick → world axes; config refusal by path; then **live**: a real Colyseus server,
  two `@colyseus/sdk` clients — each predicted its own player for 150 inputs with **0 corrections**
  (81 matches each), device hash = room hash, each saw the other move and the bot move ~5 m, and
  was told of the other's jumps / landings.
- **Load test** `scripts/room-load.mjs --3d` (16 devices, 60 ms ± 20 ms): 30.1 steps/s of 30,
  19.2 states/s of 20, 6.5 KB/s a device, step p99 0.6 ms, 10 % of a core — within budget.

## Open items / next

1. **Auto-opaque guard (step 1).** On a solid-colour page the Pixi context is created without alpha
   (`pixi-svelte` `AUTO_OPAQUE`), before the play field mounts, so the world shows black; the boot
   above used `?opaque=0`. `arcade3d` must start with a transparent Pixi canvas without changing
   the four runtimes' bytes.
2. **A 3D layout suppresses the coded `<Background>`** with a `space: 'background'` scene (an empty
   container suffices; `hasAuthoredBackground`). Game Maker's 3D scaffold should write it.
3. Phase 1 per `docs/design/3d-games.md` §6: two-canvas integration (resize, DPR clamp, pointer
   forwarding, `renderQuality`, pause on hidden tab), bodies → objects, the tier chooser.
4. Desktop / delivery builds: `buildFamilies()` infers families from a baked config; the same
   inference must turn `PUBLIC_IE_3D` on once the config switch exists (the gameplay report names it).
5. **1b leftovers:** the 3D device client — joining `arcade3d` from `apps/lines` `online.ts`
   (`world3d` read from the raw config), sending `Input3d` from the camera, feeding
   `createPredictor3d` / `createInterpolator3d` into `engine-3d`'s `sync` — is not wired (the 3D
   view lands first). The Game Config UI does not keep `arcade.world3d` yet (it normalises it away):
   a 3D config is hand-written until the level step (Phase 3, gameplay §5–6).
6. Make `runtime-bytes` a required check (it always reports; ~4.5 min on CI when engine paths change,
   seconds otherwise) — an owner ruleset change. Until it is, the manifests drift: #1699 and #1709
   merged after #1707's manifests were recorded and `main`'s own run failed; #1712 re-recorded them
   from `main`'s artifact.
