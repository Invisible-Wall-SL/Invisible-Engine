# 3D games — status

> Design: [docs/design/3d-games.md](../design/3d-games.md) · Evaluations: [docs/design/3d/](../design/3d/) · Knowledge: [docs/knowledge/families/3d.md](../knowledge/families/3d.md) · Agent: `.claude/agents/games-3d.md`

**One-line state:** the four released runtimes stay byte-identical with `three` and the `arcade3d`
seam in the workspace (0a). `arcade3d` plays offline (1a) and online in a 3D room (1b, runtime
step 4) with placeholder capsules on a placeholder arena, under the HUD, at the tier T1 chooses.
Phase 1c's `models` asset class derives, exports, bakes and pulls tiered GLBs, but **nothing draws
them yet**: no loader in `engine-3d` (GLB / KTX2 / meshopt), no upload page, and the chooser does
not read the baked index. Phases 0b (iOS determinism) and 0c (Blender toolchain) are their own
sessions.

## Current state

- **Byte isolation (PR 1, #1707).** `IE_REPRODUCIBLE=1` pins what made two builds of one commit
  differ (`__IE_BUILD__` `builtAt` / `sha` / `engineSha` / `gameSha` / `lockfileSha256`, SvelteKit's
  `kit.version.name`). `pnpm check:runtime-bytes` builds every runtime as the release does (hidden
  source maps, so each chunk carries its debug ID) and compares every file it ships — `index.html` and
  `_app/immutable/**` with their gzip size, every other file (the `static/` art, audio, fonts) by hash —
  with `scripts/runtime-bytes/<id>.json`. The `runtime-bytes` workflow runs it when a change under
  `apps/lines/`, `packages/` or the lockfile reaches a runtime; on `main` that is decided against the
  last push whose run BUILT, so a cancelled or skipped run cannot hide an engine merge
  (`--reaches`). A push release builds the reproducible twin first (with hidden source maps too) and
  ends "unchanged" without moving a pointer whose release recorded the same whole-build hash. Detail: [engine status](engine.md) "Recent changes" 2026-11-17.
- **The seam (PR 2, #1712).** `packages/engine-3d` (`three@0.181.2`) drew one toon-shaded spinning
  cube in its own fixed canvas, under the Pixi canvas (today `mountWorld3d({ canvas, caps })` with
  `setLevel` / `sync` / `pick` / `setAim`, below). `families/arcade3d.ts` re-exports the arcade seam with
  `ArcadeStage3D.svelte`, which renders the stock `<ArcadeStage>`, makes the Pixi background
  transparent, and `import('engine-3d')`s the world, synced from the Pixi ticker. `config-vite`
  resolves `families/arcade` to it only under `PUBLIC_IE_3D=1` (`compiled3d`, which throws without
  arcade). Fifth row `arcade3d` (`release: 'dispatch'`) in `constants-shared/runtimes.ts`; a push
  releases `PUSH_RELEASED_IDS` (the four); release and rollback offer `arcade3d`;
  `check-family-runtime.mjs` requires the 3D markers in `arcade3d` and forbids them elsewhere.

### Phase 1a — the 3D view (runtime steps 1–2)

- **Two canvases, guarded.** `families/arcade3d.ts` puts the world canvas on the page at import
  (`game/world3dCanvas.ts`: fixed, full-window, `z-index: -1`, hit-testable) — before the Pixi
  context exists — so `pixi-svelte`'s auto-opaque check finds a non-ancestor under its canvas and
  creates the context **with alpha**. No `?opaque=0`, no shared file. While the 3D field is
  mounted the stage sets the coded `<Background>` band (`LAYER_BAND_BACKGROUND_CODED`) to
  `renderable = false`, so a layout needs no empty background scene.
- **The stage** (`ArcadeStage3D.svelte`): offline it runs `engine-3d` `createPlay3d` — one
  `motion3d` player on the placeholder arena (`sampleArena3d`: floor with a pit, walls, a 2.5 m tier
  with two ramps, a stair, a slab, pillars, a trampoline) at the fixed 60 Hz step, interpolated,
  catching up at most 250 ms; arrows / WASD move relative to the camera, Space jumps, Shift
  sprints (`listenKeys3d`; stick → int8 axes in `moveAxes`). Online it renders the stock
  `<ArcadeStage>` (the 3D room is runtime step 4). It registers the determinism probe
  (`state().arcade`: steps, the player's x / y / z).
- **The world** (`mountWorld3d({ canvas })`): `setLevel(colliders)` draws boxes and outward-wound
  ramp wedges; `sync(bodies, view)` moves one capsule-with-a-nose per body and places the camera;
  `pick(clientX, clientY)` ray-casts the level, else the ground plane; `setAim` shows a ring.
  1024² PCF shadows (the `half` column until T1 sets caps).
- **Camera rig:** `camera.js` follows the player in metres (dead zone, smoothing, look-ahead) and
  `rigPosition` places the camera from pitch / yaw / distance / FOV, read from the play-field
  screen's `camera.rig3d` block (`resolveRig3d`; every field optional, clamped).
- **Pointer forwarding:** a pointer on the Pixi canvas where `rootBoundary.hitTest` finds no
  interactive object (or only the stage) aims in the world; the player turns toward the point.
- **DPR, resize, quality, pause:** the 3D canvas renders at `min(device DPR, 1.5)` × the 2D
  render-quality controller's current/start resolution (floor ×0.5), while the HUD keeps its own;
  re-fitted on resize. A hidden tab steps and draws nothing and resumes where it stopped.
- **Gate:** `pnpm check:engine-3d` (50 checks; discovered by `check:all`): rig resolve and clamps,
  camera placement, camera-relative int8 axes, facing, the offline loop (lands, walks, jumps
  ~1.5 m, climbs the ramp to 2.5 m, respawns past `killY`, caps catch-up, interpolates), the follow.
  `scripts/playtest/arcade3d-play.mjs` boots a build and plays it (`--serve` to play by hand).

### T1 — the tier chooser and caps

- **Chooser** (`engine-3d` `src/pure/tier.ts`, tier ids from `constants-shared/modelTiers.ts`): the
  build pin (`__IE_MODEL_TIER__`) beats `?tier=`, which beats the player's Graphics setting
  (`localStorage` `ie.graphics3d`: auto / low / medium / high / ultra), which beats auto. Auto:
  phone → `quarter`, desktop → `half`; one step down with no ASTC / BC7 / S3TC / ETC2; `quarter` under
  2048 textures or on a software renderer (SwiftShader, llvmpipe, Microsoft Basic Render — a
  blocklist only); never device memory; never `full` or `ultra`. Among the tiers a build published,
  a choice walks UP to the nearest copy (the player asked for at least that), auto stays on the web
  tiers and takes `full` only when the build has nothing else. `High` is offered only on a desktop;
  `Ultra` only past the gate (desktop, BC7 or ASTC, ≥ 8192 textures, hardware renderer; the frame
  probe is T7) and with `ultra` files.
- **Caps** (`CAPS_3D`, runtime eval §5.3): 3D pixel-ratio cap (device / device / 1.5 / 1.0), MSAA,
  shadow map 4096 / 2048 / 1024 or blob shadows on `quarter`, casters, post (none below `full`), LOD
  bias, draw distance, anisotropy, and the scene budget (`MODEL_SCENE_BUDGETS`). The stage chooses
  at mount and hands the caps to `mountWorld3d`; the published list is every tier
  (`ArcadeStage3D.svelte` passes `MODEL_TIERS`): the models index is baked into the bundle (1c)
  but nothing reads it yet.
- **The pin:** `config-vite` `artTierPin.js` `PINNABLE_TIERS` is now the four model tiers;
  `quarter` / `ultra` throw in a 2D build. A 3D build compiles the pin as `__IE_MODEL_TIER__` and
  the 2D tier it stands for (`quarter` → `half`, `ultra` → `full`) as `__IE_ART_TIER__`, so
  `chooseArtTier` never sees a 3D tier; the pull drops 2D art by that 2D tier
  (`check-art-tier-pin.mjs`). The models pull drops MODEL files by the pin itself (1c, below).
- Verified (local `arcade3d`, DPR 2): auto → `half (auto-desktop)`, world ratio 1.5;
  `?tier=quarter` → 1.0 with blob shadows; `?tier=full` → 2.0. `check:engine-3d` 98 checks
  (run 2026-11-18).

### Phase 1b — simulation and online (2026-11-17)

- **`motion3d` for gameplay** (new exports): `zonesAt3d`, `createTracker3d` / `trackStep3d` —
  edge signals `jumped` `doubleJumped` `landed` `bounced` `leaveZone` `enterZone` (`{ zone, kind }`)
  `fell` (the death plane, once per fall). Replay `d3eac484` unchanged; the spike page rebuilt.
- **`online3d.js`** (not in `index.ts`; `engine-mechanics/src/online3d.js`): `Input3d`
  `{ seq, moveX, moveZ, buttons, yaw, pitch, view }` + `sanitizeInput3d` (exact, idempotent);
  `stepPlayer3d`; `respawnOnFall3d`; `ANIM3D` / `animBits3d`; device helpers `moveFromStick`,
  `yawFromRadians`, `radiansOfYaw` (trig before quantising, never in the step);
  `createPredictor3d` (whole-body history), `createInterpolator3d` (x/y/z lerp, yaw the short way,
  `anim`), `createSnapshotClock` re-exported; `createBot3d` / `botInput3d` (a `behaviours.js` brain
  on the x/z plane, server-only); `world3dOf` / `motionFor3d` for the config.
- **The config switch is `arcade.world3d`** (`{ level: { colliders, zones, cellSize?, killY? },
motion?, characters?: { <id>: motion }, spawns? }`), read from the RAW doc by the server's
  `configSource` (`ServedGame.world3d`): `game-config` drops it, so no runtime's bytes change. The
  rest of the game is the ordinary `arcade.online` block (rates, seats, characters, bots).
- **The room:** `services/game-server` `roomSim3d.ts` + `arcadeRoom3d.ts`, room name `arcade3d`
  (`ROOM_NAME_3D`), schema `Input3D` / `Player3D` (`x y z` float32, `yaw` uint16, `status`, `team`,
  `anim`, `ack`, name, character, connected, bot) / `RoomState3D` (`phase`, `step`, `seed`). The 2D
  room refuses a `world3d` game and the 3D room any other; the 2D classes are untouched. Teams
  balance by BOTY's rule; one-shots are `ONLINE_EVENT` messages.
- **The fold rule:** a 3D player is stepped ONLY by an input (no step without one: a stall or a
  drop freezes it, mid-air included), and the death-plane respawn is part of the fold. So the
  device's prediction equals the room to the bit under any latency — 0 corrections measured.
- **Gate `pnpm check:room-sim-3d`** (11 checks, ~15 s): 6000 steps × 2 devices through a jittery,
  stalling link — 12 400 room/fold hash comparisons equal, 0 corrections, 24 respawns, 149 jumps,
  19 bounces, 498 ramp steps; clamp; drop/rejoin; seats/teams; bots chase and replay by seed;
  interpolator; stick → world axes; config refusal by path; then **live**: a real Colyseus server,
  two `@colyseus/sdk` clients — each predicted its own player for 150 inputs with **0 corrections**
  (81 matches each), device hash = room hash, each saw the other move and the bot move ~5 m, and
  was told of the other's jumps / landings.
- **Load test** `scripts/room-load.mjs --3d` (16 devices, 60 ms ± 20 ms): 30.1 steps/s of 30,
  19.2 states/s of 20, 6.5 KB/s a device, step p99 0.6 ms, 10 % of a core — within budget.

### Runtime step 4 — online 3D in the stage

- **Joining:** `families/arcade3d.ts` exports `game/online3d.ts`'s `joinOnlineRoom` in place of the
  2D one. A config with an `arcade.world3d` block joins the game server's `arcade3d` room
  (`?rooms_url=`, `?rooms_game=`, `?rooms_name=`, `?rooms_character=`, as in 2D); any other online
  game joins the 2D room through the 2D client, unchanged. A room that closes stops the game on
  the error screen.
- **The device side** (`engine-3d` `createRoomView3d`, pure): an input each of the room's fixed
  steps (`tickHz`; the stick through 1b's `moveFromStick` at the camera's yaw, facing the move or
  the aimed point), the own player predicted by `createPredictor3d` from the first state that
  shows it (its home, exactly), everyone else interpolated by `createInterpolator3d` ~100 ms behind
  (`createSnapshotClock`), a player who leaves dropped. The stage draws it through the same
  `mountWorld3d`; the level is the room's own `arcade.world3d`.
- **Gate `check-engine-3d-room.mjs`** (7 checks): two devices at 60 fps through 40–120 ms links
  play 1b's real `createRoomSim3d` (30 Hz, patches 20 Hz) for 40 s — ~1,200 inputs each, every one
  applied, the own body bit-equal to the room's with **0 corrections**, the other drawn where the
  room has it once still, up walks to −z, a leaver is dropped. A planted wrong `dt` fails it.
- **Live** (`arcade3d-play.mjs --online --serve`: the sample with an `arcade.online` block and the
  arena as its `world3d`, a game server in the process): two Chromium windows joined one room; each
  drew its own player (orange) and the other (blue) where the other walked and jumped.

### Phase 1c — the `models` asset class (assets track)

- **Tiers as data (#1715).** `constants-shared/modelTiers.ts`: `MODEL_TIERS` (`ultra`, `full`,
  `half`, `quarter`), per-class defaults (LOD windows, map caps / drop / encoding, generated-LOD
  targets, `lodScreenSize`, scene budgets), `modelMapSize`, `modelTierFile`, `publishedModelTiers`;
  `constants-shared/models.ts`: the types-only `ModelExportIndex`. No 2D code imports either
  (`runtime-bytes` green). Never in engine-layout `RESOLUTION_TIERS`.
- **Optimiser (#1720).** `launcher-api` `modelOptimize.ts` (glTF-Transform 4.5.1 + meshoptimizer 1.3.0):
  one tier from one master — the tier's window on `_LOD<n>` / `_LODU`, missing levels generated
  from the nearest richer level (whole chain first, so a level is the same file in every tier;
  error bound loosened ×3 up to three times; `simplifySloppy` for a prop's last level; tiles lock
  only their footprint edges with `Permissive` instead of meshopt's `LockBorder`, which locked every
  UV seam), maps resized from the master, normal / ORM dropped on `quarter` with AO multiplied into
  base colour, KTX2 with mips, then dedup / prune / resample / meshopt (+ quantisation). Textures
  stay external (`_tex/<hash>[@tier].<ktx2|png>`, the hash = the encode cache key: role, size,
  encoding, master image, the AO baked in, both revisions): our own GLB packer, since
  glTF-Transform's embeds images. A quantised master (`KHR_mesh_quantization`) is dequantised
  before the LOD step. Caps (`MODEL_LIMITS`): 32 images, 8192² a side, 1 M vertices, 2 M
  triangles, 512 MiB of decoded geometry — read from the GLB's JSON chunk before anything
  decodes, refused at upload (`MODEL_OVER_LIMIT` / `TEXTURE_TOO_LARGE`), skipped with a warning
  by the export, thrown by the derive; on top of the 256 MB upload size. `ktx2Encode.ts` gained `encodeModelTextureToKtx2` (ETC1S or
  UASTC, sRGB or linear, normal-map mode, mips); `encodePageToKtx2` is untouched.
- **The class.** Upload = presign to `models/<id>/uploads/<uuid>.glb`, then `POST
/api/models/register` validates, writes the master content-addressed (`source.<sha12>.glb`,
  create-only) and commits `model.json` by CAS (`baseEtag` required). `modelExport.ts` through the
  registry (`models`, bake policy `additive`) and a `DeployMirror`: models a doc names in a
  `modelId` / `modelIds` field (layout and Game Config, read raw), `full` + each tier the raw
  `resolutionTiers` names, a tier equal to `full` byte for byte not written, an R2 texture cache
  in `models/_cache/`. Bake and `RuntimeBundle.models` embed the index only when non-empty; the game
  side is only a type (`BakedBundle.models`): no runtime code reads it yet (the comment on it in
  `apps/lines/src/editor-scenes.ts` says the view loads `deploy/models/` — it does not). Pull: `models` joined
  `GENERATED_SUBTREES` (the evaluation's "no change" was wrong: the pull skipped every model
  file); `artTierDrop` drops `models/` files by the pin itself (#1727's four-tier pin), while 2D
  art keeps 1a's rule by the 2D tier the pin stands for: a pin to X drops every other model
  tier's copies and the full files with an X copy, a model texture ships only when a kept GLB
  names it, and `.glb` is a descriptor. Gates:
  `check:model-optimize`, `check:model-export`, `check-art-tier-pin.mjs` 2b.

## Open items / next

1. **Published tiers:** the chooser treats every tier as published. 1c's models index is now
   baked into the bundle; the stage still has to read it and pass the tiers it lists. The Graphics
   setting control itself is T4 (contributed by the 3D seam, never the shared HUD).
2. **The level is the config's `arcade.world3d`** (`engine-3d` `playField3d`, through 1b's
   `world3dOf` on the raw doc: the level, the first spawn and its yaw, the motion — the block the 3D
   room reads, so a level plays the same offline and online). A config without the block shows the
   placeholder `sampleArena3d()`; a bad one logs its first bad path and shows the placeholder.
   Authoring levels is gameplay §5 (the seeded generator, then the Blender import). The arcade
   sample's 2D flow still spawns into its spawn layer (capped, never moved, off screen) — a 3D layout
   authors no 2D spawners.
3. **Online 3D follow-ups:** the room's one-shots (`jumped`, `landed`, `enterZone`, …) are
   received but not yet raised as Flow signals; the lobby, names, teams and the per-player
   character (`?rooms_character=`) are not drawn; reconnection after a drop is the SDK's default.
4. Desktop / delivery builds: `buildFamilies()` infers families from a baked config; the same
   inference must turn `PUBLIC_IE_3D` on once the config switch exists (the gameplay report names it).
5. **1b leftover:** the 3D device client is wired (runtime step 4). The Game Config UI does not
   keep `arcade.world3d` yet (it normalises it away): a 3D config is hand-written until the level
   step (Phase 3, gameplay §5–6).
6. Make `runtime-bytes` a required check (it always reports; ~4.5 min on CI when engine paths change,
   seconds otherwise) — an owner ruleset change. Until it is, the manifests drift: #1699 and #1709
   merged after #1707's manifests were recorded and `main`'s own run failed; #1712 re-recorded them
   from `main`'s artifact. A cancelled run used to hide an engine merge as well (fixed by `--reaches`,
   2026-11-18 below).
7. **`ultra` 4096² maps cannot be encoded**: `ktx2-encoder` refuses more than ~12 Mpix, so the
   derive halves such a map to 2048² (= `full`'s) and `ultra` ships no copy of it. Needs basisu
   native or a newer encoder; `ultra` is Phase 5 anyway.
8. **Game Config `models` block**: the export reads `config.json` RAW (`models.profiles`,
   `models.lodScreenSize`); the Game Config normaliser (`engine-game` `gameConfig.ts`) does not know
   the block yet. Not checked: whether a Game Config save drops it or refuses the doc. The UI PR
   adds it to the doc type (in every bundle, so with a `runtime-bytes` look).
9. **Model Viewer (Phase 4)**: `/api/models` (list), `/api/models/upload`, `/api/models/register`
   exist with no page; they are gated on the `editor` or `characters` tool until `/models` is
   registered (rule 9). Staged uploads (`models/<id>/uploads/`), superseded or lost-race sources and
   `models/_cache/` are not swept yet (a lifecycle rule needs a fixed prefix: move staging to a
   global `_staging/models/`; old sources need a mark-and-sweep against `model.json`). The
   Viewer must take a lease when it ships (`pipeline-concurrency` review, 2026-11-17).
10. **Overlapping exports** (a publish and a runtime assemble with inputs changing between them): the
    first `DeployMirror.commit` deletes keys the other pass wrote, so its `index.json` can name
    missing files. Every exporter shares this; models widen the window (deriving takes seconds to
    minutes). Needs a per-project export lock or a two-phase commit.
