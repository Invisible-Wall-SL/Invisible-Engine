# 3D games — status

> Design: [docs/design/3d-games.md](../design/3d-games.md) · Evaluations: [docs/design/3d/](../design/3d/) · Knowledge: [docs/knowledge/families/3d.md](../knowledge/families/3d.md) · Agent: `.claude/agents/games-3d.md`

**One-line state:** Phase 0a (size isolation) done — the four released runtimes stay byte-identical
with `three` in the workspace and the `arcade3d` seam present; `arcade3d` boots with a toon cube
under the HUD. Phases 0b (iOS determinism) and 0c (Blender toolchain) are their own sessions.

## Current state

- **Byte isolation (PR 1, #1707).** `IE_REPRODUCIBLE=1` pins what made two builds of one commit
  differ (`__IE_BUILD__` `builtAt` / `sha` / `engineSha` / `gameSha` / `lockfileSha256`, SvelteKit's
  `kit.version.name`). `pnpm check:runtime-bytes` compares every file under `_app/immutable/` +
  `index.html` of every runtime with `scripts/runtime-bytes/<id>.json`; the `runtime-bytes` workflow
  runs it on any change under `apps/lines/`, `packages/` or the lockfile. A push release builds the
  reproducible twin first and ends "unchanged" without moving a pointer whose release recorded the
  same whole-build hash. Detail: [engine status](engine.md) "Recent changes" 2026-11-17.
- **The seam (PR 2).** `packages/engine-3d` (`three@0.181.2`, `mountWorld3d(host, opts) → { sync,
resize, destroy }`) draws one toon-shaded spinning cube in its own fixed canvas, inserted before
  the Pixi canvas and blind to the pointer. `families/arcade3d.ts` re-exports the arcade seam with
  `ArcadeStage3D.svelte`, which renders the stock `<ArcadeStage>`, makes the Pixi background
  transparent, and `import('engine-3d')`s the world, synced from the Pixi ticker. `config-vite`
  resolves `families/arcade` to it only under `PUBLIC_IE_3D=1` (`compiled3d`, which throws without
  arcade). Fifth row `arcade3d` (`release: 'dispatch'`) in `constants-shared/runtimes.ts`; a push
  releases `PUSH_RELEASED_IDS` (the four); release and rollback offer `arcade3d`;
  `check-family-runtime.mjs` requires the 3D markers in `arcade3d` and forbids them elsewhere.

## Open items / next

1. **Auto-opaque guard (step 1).** On a solid-colour page the Pixi context is created without alpha
   (`pixi-svelte` `AUTO_OPAQUE`), before the play field mounts, so the world shows black; the boot
   above used `?opaque=0`. `arcade3d` must start with a transparent Pixi canvas without changing
   the four runtimes' bytes.
2. **A 3D layout suppresses the coded `<Background>`** with a `space: 'background'` scene (an empty
   container suffices; `hasAuthoredBackground`). Game Maker's 3D scaffold should write it.
3. Phase 1 per `docs/design/3d-games.md` §6: two-canvas integration (resize, DPR clamp, pointer
   forwarding, `renderQuality`, pause on hidden tab), bodies → objects, the tier chooser.
4. Desktop / delivery builds: `buildFamilies()` infers families from a baked config; the same
   inference must turn `PUBLIC_IE_3D` on once the config switch exists (the gameplay report names it).
5. Make `runtime-bytes` a required check (it always reports; ~4.5 min on CI when engine paths change,
   seconds otherwise) — an owner ruleset change.

## Blocked (owner / external)

- Requiring `runtime-bytes` on `main` is the owner's ruleset setting.

## Recent changes

- 2026-11-17 — **Phase 0a: size isolation proven** (#1707, then the seam PR). Two findings that
  contradict the plan's assumptions: the manifests must be **Linux's** (a Windows `autocrlf`
  checkout builds other bytes: CSS +264 B, bundle ~+450 B, `libktx.js` −12 B gz), so they are taken
  from CI's `runtime-bytes` artifact; and the two-canvas layering needs the auto-opaque guard and an
  authored background scene before a 3D game shows its world (open items 1–2).
