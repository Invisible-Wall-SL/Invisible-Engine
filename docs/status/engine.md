# Engine & games — status

> Design: [flow-driven-game](../design/flow-driven-game.md) · [live-assets](../design/live-assets.md) · [games-deploy](../design/games-deploy.md) · Agent: `.claude/agents/engine-pixi-svelte.md`

**One-line state:** Shipped — the shared runtime (`runtime:lines`, built from `apps/lines` + `packages/*`) carries every scoped feature on `main`; the `apps/{lines,cluster,ways,scatter,number-picker,price}` are dev/reference games, and only `lines`/`bookOf` have rich reference scene sets.

## Current state
What runs on `main` today (this is the ENGINE side — the runtime + reference games, not a launcher tool). Online games run the SHARED `_runtime/lines` bundle; `apps/lines` is its source.

- **Symbol sizing** — sprites are plain `contain`-fit to the cell by their native art aspect; SPINE symbols contain-fit the rig's setup-pose bounds to `SYMBOL_SIZE × SYMBOL_SPINE_FILL` (spine-only shrink constant, `apps/lines/src/game/constants.ts`, started 0.5). The old `sizeRatios` param + the Scene Editor "Symbol size (× cell)" control were removed from the render equation (size comes from the ART, not a number; oversize spines are fixed by tightening the rig bounds in the Rigger). Cross-origin alpha-trim of sprite textures was tried and reverted (tainted `getImageData` — don't retry).
- **Persistent background scene** — a `space:'background'` scene renders behind the game for the whole session (`engine-layout/backgroundScenes.ts`), cover-fit as one group so multi-part backgrounds keep their real size + animate (`ComponentInstance` cover path).
- **Bitmap-font layout text** — `LayoutNodeView` renders `<BitmapText>` for authored bitmap fonts via `registerFontCatalog`; coded HUD/label text honors authored bitmap fonts through the shared `engine-layout/CatalogText` component (one source, canvas `<Text>` + `<BitmapText>` can't drift).
- **Component value/defaults + HUD readouts (B1–B3)** — the component value/defaults system + Balance/Win/Bet readouts are wired behind the parity gate; B4 (converting the live readouts to component instances) is still open.
- **Per-sheet editor-art namespacing** — editor-art regions are scoped `<assetKey>::<region>` so a new sheet no longer shadows an older same-named region.
- **Generic doc-driven scene mounting (Editor §20.1)** — an author's new Scene Editor screen (custom id, non-background space) ships in the game without being hardcoded in `Game.svelte`: `engine-layout/genericMountScenes.ts` `extraMountScenes(scenes, reservedIds)` renders them in doc order behind a parity-gated `{#each}` (empty reserved-set ⇒ byte-identical). FlowDoc-authored screens are folded into the reserved set to avoid double-mount.
- **Win-line renderer in the SHARED engine** — ported from the standalone Book of Borut into `apps/lines` (`806d6cf`): `WinLine.svelte` (Graphics polyline, optional layered-stroke glow, optional `svelte/motion` animated draw, bitmap win-amount text), resolved from the sparse `bundle.symbols.winLine` (`bakedWinLineConfig()`/`bakedWinLineEnabled()`, runtime→baked precedence). Default-ON, so every `runtime:lines` game draws it unless disabled in `/symbols`.
- **Full-screen camera effects** — `shake` / `flash` / `zoomPunch` / `chromaticWobble`, authored from Flow as ONE `cameraEffect` action with a `kind` dropdown (adding a flourish must not grow the palette an entry each). Implemented engine-side in `pixi-svelte/src/lib/cameraEffects.ts` against the **`Application.stage`** — `<App>`'s children are flat z-banded siblings, so the stage is the only transform that moves board + HUD + overlays together (it moves `<DebugStage>` too; accepted). Effects **compose**: each contributes a per-frame sample and one compositor applies the sum, so overlapping effects can't fight over `stage.position`; the resting transform is captured up front and restored exactly when the last effect drains, and the ticker callback is removed at rest (zero idle cost). `intensity` is a **multiplier of a per-kind reference** (24px / 8% / 0.85 alpha / 12px), not pixels — capped at 4. `blocking` (default false) picks whether the interpreter awaits it. Kinds live in `constants-shared/camera` and are read by BOTH the vocab enum and the implementation, so the editor can't offer a kind the game would no-op. Off unless authored (no FlowDoc references it yet ⇒ byte-parity).
- **Free-spin sequential reel stop** — a timing-only `sequential` spin mode (reels settle consecutively in free spins, no anticipation glow/SFX). Off by default (byte-parity when unused); Flow-toggleable via `enableSequentialReelStop`/`disableSequentialReelStop` effects with per-reel `gaps`/`speeds` (`list<float>`). Engine plumbing added a `'sequential'` `SpinType` member across `utils-slots`.
- **Three-knob reel grid** — the conflated `reelPadding` was split into three orthogonal `ReelGridNode` knobs, all default-to-identity (byte-parity): reel/row **LEAD** (`reelPadding`/`rowPadding`, seats the cluster), seat **ALIGNMENT** (`symbolAlignX/Y`, art within its cell), board **NUDGE** (`boardNudgeX/Y`, px offset). Editor `drawReelGrid` mirrors the game math exactly (editor↔game < 1e-12 px).
- **Slam stop (mid-spin quick stop)** — ALWAYS ON, no config toggle. A press while a round runs snaps the reels to the already-resolved result AND fast-forwards the post-reveal presentation (count-ups jump to the final total, win lines draw complete, player-gated holds release) so the machine returns to idle promptly. The token is scoped to the **ROUND**, so on a bonus book ONE press fast-forwards every remaining free spin to the final total. During **autoplay** the first press slams the current spin only; a **second** press cancels the remaining sequence (autoplay is therefore always cancellable, in at most two presses). Built on a new `utils-shared/skipToken` primitive + the shared `utils-shared/spinStop` press/key helper (which de-duplicates the spin/stop logic that was copied verbatim into `ButtonBetProvider` and `Game.svelte`). Skipping never DROPS a beat: every book event still runs, fully awaited, and applies its effect at final value — only the time is removed.
- **Live-asset pipeline** — a game asset only ships when it travels the full chain **export → `deploy/` → bake (embed index in bundle) → pull (mirror into `static/assets/`) → runtime register** (CLAUDE.md rule 8; `docs/design/live-assets.md`). Exported sheets are content-versioned (`sheetVersion` hashes region geometry + source-page ETag) so a re-packed atlas busts the cache automatically; exporters emit a `missing[]` dangling-binding guard. "Shows in the editor" ≠ "ships" — the editor reads R2 directly.
- **How the runtime ships** — an engine/runtime change reaches online games ONLY via a runtime-bundle publish, NOT a `main` merge. **Preferred: the `Runtime release` GitHub Action** (`.github/workflows/runtime-release.yml`) — a manual `workflow_dispatch` ("Run workflow", or `gh workflow run runtime-release.yml -f runtime=lines`) that does the whole chain with the R2 keys held in GitHub Actions secrets, so a release needs no keys on a dev machine. Game Maker's Publish CANNOT do it: `publishGame` only points a game's manifest at the prebuilt `_runtime/<id>` and "never rebuilds". The equivalent manual chain: rebuild the `engine-layout` **dist** first (stale-dist trap), then `PUBLIC_RGS_TRANSPORT=play4fun pnpm --filter lines build`, then `node apps/launcher-api/scripts/publish-runtime-bundle.mjs lines apps/lines/build`, then `POST https://games.invisiblewall.org/refresh`. Shipped standalone games (e.g. Book of Borut) instead bump their `engine` git submodule to a `main` commit (owner-owned). Standalone Borut keeps its OWN `src/game/*` copies, so game-side wiring (flags/effects/constants) must be MIRRORED there — the submodule only delivers `packages/*` engine code.

⏳ Live-verify caveats still open: `SYMBOL_SPINE_FILL`'s live size judgement (0.5 tunable); the z-order of author extra-scenes (currently above the HUD) is a live tuning call; the win-line line-draw and sequential-stop timing were shipped + reachability-verified but not auto-verified in a live spin (owner confirms by forcing the win / triggering free spins).

- 2026-07-20 — **Slam stop: the free-spin outro hold now releases on a slam (hang fix).** Owner report: "the game breaks during free spin if I slam stop just before the free spin win". `showContainer{awaitComplete}` — the flow-v2 round-block hold, shipped as a KNOWN gap with af71840 — was the ONLY await left in the round chain that a slam could not release: every cue, delay and cut-short effect races `roundSkip`, but that hold is resolved solely by a tap on a `tapToContinue` overlay. In a flow-driven game the free-spin outro IS that tap gate, so a slam fast-forwarded the whole feature and then parked on it. Two things made it a dead end rather than a wait: `runSpinOrSlamStop` early-returns once the token is tripped, so the spin button the player presses next does nothing, and that button is drawn above the overlay, so it swallows the very tap that would have released the hold. The round then never completes ⇒ `playBet` never returns ⇒ the machine never reaches idle. `playBet`'s `try/finally` cannot save it: an un-settled await is not an exception, so the `finally` never runs. Fixed in `apps/lines/src/game/flowV2Runtime.svelte.ts` with a slam-aware mount wrapper — `awaitComplete` registers the hold, then subscribes `roundSkip.onSkip` to `mount.complete(id)` (subscribed AFTER registration, because `onSkip` fires synchronously on an already-tripped token). Completing is exactly what the tap does, so the same exec chain resumes show → hide → next and no beat, state write or win is dropped. The wrapper is applied unconditionally; the `?flowlog=1` trace wrapper now delegates through it (it previously wrapped `rawMount`, so a fix placed there would only have existed with tracing on). **Coded and v1-flow paths were never affected** — every hold in `bookEventHandlerMap`/`flowEffects`/`flowRuntime` is raced, and a Node harness driving the real svelte `Tween` + `interruptible` + `skipToken` on a fake raf clock confirmed `reel.spin()` settles for a slam at every point in the roll AND for a reel whose spin STARTS with the token already tripped (the next free-spin reveal), so the fully-awaited `enhancedBoard.spin()` cannot strand the round. Only apps/lines runs flow-v2 ⇒ no other app affected. **Needs a runtime publish to reach online games** (shared `_runtime/lines` bundle) + a submodule bump for standalone `bookofborut`.
- 2026-07-20 — **Slam stop implemented end-to-end (reels + win presentation).** It was ~60% built but gated to autoplay: `ButtonBetProvider.getKey()` returned `spin_disabled` for a rolling SINGLE bet ("a single bet's roll has nothing to stop"), and the identical logic was duplicated verbatim in `Game.svelte`. Four faults, all fixed:
  - **The button was inert.** The key/press decision now lives ONCE in `packages/utils-shared/spinStop.ts` (`getSpinButtonKey` / `runSpinOrSlamStop`), shared by `ButtonBetProvider.svelte`, `Game.svelte`'s registered `spin` action and its replacement Space hotkey. A rolling round shows a live STOP. The `stopDisabled` latch (which made a second press a no-op) is GONE — a second press has to be able to cancel autoplay. `SpinButtonKey` lost its `stop_disabled` member, which nothing could produce.
  - **Anticipating reels were un-slammable.** `createReelForSpinning`'s `noStop` branch awaited `slideDown()` OUTSIDE `interruptible.add`, so an anticipation reel could not be interrupted at all. It now always routes through the interrupt, with an explicit slam (`roundSkip.isSkipped()`) overriding `noStop` — which also covers the reel that has not STARTED rolling when the press lands, something `interruptible` cannot do (it only cuts an in-flight wait). `reel.stop()` clears `anticipating`, and `createEnhanceBoardSpin` no longer ARMS a new anticipation on a slammed round.
  - **The post-reveal phase was not skippable.** New primitive `packages/utils-shared/skipToken.ts` — `createSkipToken()` + the `roundSkip` singleton: `isSkipped/skip/reset/onSkip/wait/race`. STICKY (`onSkip` fires immediately for a late subscriber), which is what lets ONE press fast-forward everything that mounts after it. `runSpinOrSlamStop` trips it SYNCHRONOUSLY before broadcasting `stopButtonClick`, so no subscriber-ordering dependency exists. Re-armed per ROUND in `playBet` and nowhere else — a bonus book is one round, so one press covers the whole feature. `WinCountUpProvider` finishes on skip (and starts at duration 0 if already slammed) so count-ups land on the FINAL total; `WinLine` draws complete; the hard-coded waits and awaited broadcasts in `bookEventHandlerMap`/`flowEffects` are raced/`roundSkip.wait`-ed. Book events are still ALL run and each handler still fully awaited — racing a handler would let a detached `reveal` keep spinning the reels under the `winInfo` that follows.
  - **Flow-driven presentations ignored it.** Both flow hosts inject `waitForTimeout: roundSkip.wait` and race their awaited broadcasts. The flow EFFECT registry is invoked directly by the interpreter and bypasses that wrapper, so every awaited broadcast in `flowEffects.ts` now goes through a local `awaitPresentation` helper. The registry itself is deliberately NOT raced: on a whole-feature skip that would resolve `revealBoard` instantly for all ten spins and run ten reveals concurrently on the same reels. `FlowEmitter.broadcastAsync` was narrowed `Promise<unknown[]>` → `Promise<unknown>` (the results were never read) so the game can wrap it.
  - No XState change was needed: with the waits collapsed, `playGame` resolves fast and the machine drains to idle on its own.
  - **Turbo side effect checked (`ButtonTurbo`):** `stopButtonClick` still flips a NON-persistent turbo on and `stopButtonEnable` flips it off; `updateIsTurbo(_, {persistent:false})` is a no-op while `isTurboLocked`, so a player-set turbo is never corrupted. `playBet` now broadcasts `stopButtonEnable` from a `finally`, so a throwing handler can no longer leave turbo stuck on.
  - **One press, one action.** The spin button's Space hotkey now stands down while a press-to-continue overlay is mounted (`stateUi.continuePressCount` / `hasContinuePress()`, armed by each game's `PressToContinue`) — otherwise one keypress ran both the slam and the continue-press, with `soundPressBet` over the outro music. The pointer needs no such gate: the overlay's full-screen rect and the button are separate hit targets, so a click reaches exactly one, and both fast-forward the presentation.
  - **Blast radius (shared code).** `spinStop`/`ButtonBetProvider`, the `createEnhanceBoardSpin` anticipation guard, `WinCountUpProvider`'s skip hook and `PressToContinue`'s press claim are shared, so ALL six dev games get the live single-spin STOP and the two-press autoplay cancel. `createReelForSpinning` (the `noStop`-inside-`interruptible` change + `stop()` clearing `anticipating`) reaches only **lines** and **price** — `cluster`/`ways`/`scatter`/`number-picker` use `createReelForCascading`, which is untouched. - 2026-07-17 — **Four free-spin presentation faults, all silent by construction.** Reported as "the reveal symbol never appears, the counter says `10 OF` on spin one, the book symbol vanished, the outro plays nothing".
  - **`SpineBoneAttach` could not detect a missing bone.** `follow()` probed the result of `getBonePosition(name, outPos)` for truthiness, but spine-pixi returns the passed-in scratch point UNCHANGED on a miss (it only `console.error`s). So `pos` was always truthy, the documented "never silently vanish" fallback was **dead code**, and a bad/unset bone re-applied the world transform to the previous frame's leftover `bonePoint` every tick — compounding drift plus an error per frame. Now resolves the bone first and genuinely falls back. The bone is also resolved once per frame instead of twice.
  - **The free-spin counter had no writer on the trigger chain.** `freeSpinCounterCurrent` is only ever written by `updateFreeSpinCounter` (on `updateFreeSpin`), which does not arrive until the first spin has RESOLVED — so `freeSpinCounterShow` put the counter on screen reading a value nobody wrote (0 on a first session; the previous session's final count on a repeat, since `exitFreeSpinOutro` never reset it). `setFreeSpinCounterTotal`/`…TotalOnly` now seed `current = 1` and `exitFreeSpinOutro` resets it to 0.

Now routed through the guard.

So the authored outro animation ran exactly once per page load and every later outro opened already parked on idle. `freeSpinOutroShow` now re-arms it.

  - **Gotcha found in review — `Container.filterArea` is LOCAL, not global.** `FilterSystem` does `bounds.addRect(filterArea)` then `bounds.applyMatrix(container.worldTransform)` (`filters/FilterSystem.mjs:63-66`). Setting `stage.filterArea = app.screen` therefore makes the filter bounds RIDE any stage transform — so a `chromaticWobble` composed with a `shake` clipped an unrendered strip off the screen edge, oscillating at the shake frequency (24px offset ⇒ 24px blank strip; measured).
