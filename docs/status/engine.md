## Current state

What runs on `main` today (this is the ENGINE side — the runtime + reference games, not a launcher tool). Online games run the SHARED `_runtime/lines` bundle; `apps/lines` is its source.

- **Symbol sizing** — sprites are plain `contain`-fit to the cell by their native art aspect; SPINE symbols contain-fit the rig's setup-pose bounds to `SYMBOL_SIZE × SYMBOL_SPINE_FILL` (spine-only shrink constant, `apps/lines/src/game/constants.ts`, started 0.5). The old `sizeRatios` param + the Scene Editor "Symbol size (× cell)" control were removed from the render equation (size comes from the ART, not a number; oversize spines are fixed by tightening the rig bounds in the Rigger). Cross-origin alpha-trim of sprite textures was tried and reverted (tainted `getImageData` — don't retry).
- **Persistent background scene** — a `space:'background'` scene renders behind the game for the whole session (`engine-layout/backgroundScenes.ts`), cover-fit as one group so multi-part backgrounds keep their real size + animate (`ComponentInstance` cover path).
- **Per-node cover-fit (`node.coverFit`)** — a sprite/spine node in a normal `canvas`-space (FLOW-GATED) scene can opt into true cover-fit to the window via a `coverFit` boolean on `BaseNode` (`engine-layout/types.ts`), reusing the exact `background` cover math (`coverTransform` + `backgroundCoverScale`/`backgroundFit`/`scale` stretch) WITHOUT the always-on persistent mounting of `space:'background'` — so a free-spin intro screen can host a full-screen stretched animation the flow still shows/hides. Runtime gate `isCanvasCoverFit`/`isCover` in `LayoutNodeView.svelte` (a `coverFit` spine is force-CENTRED on the canvas via `spineCoverCenter`, matching the sprite cover + the editor — it ignores authored x/y, since a flow screen places it anywhere); editor previews it WYSIWYG (`EditorCanvas.nodeTransform` + `isBackgroundCover`, `EditorSpineLayer` `coverFit` target, `+page.svelte` `isBackgroundCoverSelected`); authored via a "Cover / full-screen fill" toggle in `EditorProperties.svelte` (canvas-space sprite/spine only) that reveals the existing cover-scale/fit/stretch controls. Additive — `coverFit` unset is byte-identical, `background` scenes unchanged. Verify offline: `node packages/engine-layout/scripts/test-cover-fit.mjs`. Persistence: node fields pass through `editorStorage.normalizeNode` + `identityComponentRoot`'s child-preserving copy untouched (no allowlist), and `markDirty` always bumps the canvas redraw nonce, so no whitelist change was needed. Reaching a live game needs a runtime release + reconcile.
- **Bitmap-font layout text** — `LayoutNodeView` renders `<BitmapText>` for authored bitmap fonts via `registerFontCatalog`; coded HUD/label text honors authored bitmap fonts through the shared `engine-layout/CatalogText` component (one source, canvas `<Text>` + `<BitmapText>` can't drift). `pixi-svelte`'s `<BitmapText>` applies three font guards before pixi sees the text (`sanitizeBitmapText.ts`): a synthesised space glyph + unbaked-glyph sanitisation (the two black-screen guards) and `normalizeBitmapFontMetrics`, which corrects a descriptor that under-reports its glyph box so `fontSize` means the same thing for every font (the bundled `silver` declares 97 for 199px glyphs). The launcher's `EditorTextLayer` calls the same normaliser so the editor canvas can't drift from the game.
- **Component value/defaults + HUD readouts (B1–B3)** — the component value/defaults system + Balance/Win/Bet readouts are wired behind the parity gate; B4 (converting the live readouts to component instances) is still open.
- **Per-sheet editor-art namespacing** — editor-art regions are scoped `<assetKey>::<region>` so a new sheet no longer shadows an older same-named region.
- **Generic doc-driven scene mounting (Editor §20.1)** — an author's new Scene Editor screen (custom id, non-background space) ships in the game without being hardcoded in `Game.svelte`: `engine-layout/genericMountScenes.ts` `extraMountScenes(scenes, reservedIds)` renders them in doc order behind a parity-gated `{#each}` (empty reserved-set ⇒ byte-identical). FlowDoc-authored screens are folded into the reserved set to avoid double-mount.
- **Win-line renderer in the SHARED engine** — ported from the standalone Book of Borut into `apps/lines` (`806d6cf`): `WinLine.svelte` (Graphics polyline, optional layered-stroke glow, optional `svelte/motion` animated draw, bitmap win-amount text), resolved from the sparse `bundle.symbols.winLine` (`bakedWinLineConfig()`/`bakedWinLineEnabled()`, runtime→baked precedence). - **Full-screen camera effects** — `shake` / `flash` / `zoomPunch` / `chromaticWobble`, authored from Flow as ONE `cameraEffect` action with a `kind` dropdown (adding a flourish must not grow the palette an entry each). Implemented engine-side in `pixi-svelte/src/lib/cameraEffects.ts` against the **`Application.stage`** — `<App>`'s children are flat z-banded siblings, so the stage is the only transform that moves board + HUD + overlays together (it moves `<DebugStage>` too; accepted). Effects **compose**: each contributes a per-frame sample and one compositor applies the sum, so overlapping effects can't fight over `stage.position`; the resting transform is captured up front and restored exactly when the last effect drains, and the ticker callback is removed at rest (zero idle cost). `intensity` is a **multiplier of a per-kind reference** (24px / 8% / 0.85 alpha / 12px), not pixels — capped at 4. `blocking` (default false) picks whether the interpreter awaits it. Kinds live in `constants-shared/camera` and are read by BOTH the vocab enum and the implementation, so the editor can't offer a kind the game would no-op. Off unless authored (no FlowDoc references it yet ⇒ byte-parity).
- **Free-spin sequential reel stop** — a timing-only `sequential` spin mode (reels settle consecutively in free spins, no anticipation glow/SFX). Off by default (byte-parity when unused); Flow-toggleable via `enableSequentialReelStop`/`disableSequentialReelStop` effects with per-reel `gaps`/`speeds` (`list<float>`). Engine plumbing added a `'sequential'` `SpinType` member across `utils-slots`. **TURBO WINS over it** (`createEnhanceBoardSpin`): sequential stop is pacing the feature imposes, turbo is the player asking for pacing to be dropped, so a held turbo takes the reel back to the global `fast` spin type instead of the free-spin mode silently overriding it.
- **Three-knob reel grid** — the conflated `reelPadding` was split into three orthogonal `ReelGridNode` knobs, all default-to-identity (byte-parity): reel/row **LEAD** (`reelPadding`/`rowPadding`, seats the cluster), seat **ALIGNMENT** (`symbolAlignX/Y`, art within its cell), board **NUDGE** (`boardNudgeX/Y`, px offset). Editor `drawReelGrid` mirrors the game math exactly (editor↔game < 1e-12 px).
- **Slam stop (mid-spin quick stop)** — ALWAYS ON, no config toggle. A press while a round runs snaps the reels to the already-resolved result AND fast-forwards the post-reveal presentation (count-ups jump to the final total, win lines draw complete, player-gated holds release) so the machine returns to idle promptly. The token is scoped to the **SPIN**: in `apps/lines` the re-arm hangs off `updateFreeSpin`, the FIRST event of every free spin (not the `reveal` — the counter update leads the spin it labels, so re-arming at the reveal left the next spin's counter presented under the previous spin's tripped token), so a press slams only the spin that is rolling and the feature then resumes at full pace — normal roll, normal anticipation, normal count-up — until the next press. (Base-game rounds have a single reveal, never re-arm, and keep the round-scoped behaviour. The other five dev games are still round-scoped: their bonus mechanics are cascades, and the owner's direction was about the Book-of feature.) During **autoplay** the first press slams the current spin only; a **second** press cancels the remaining sequence (autoplay is therefore always cancellable, in at most two presses). Built on a new `utils-shared/skipToken` primitive + the shared `utils-shared/spinStop` press/key helper (which de-duplicates the spin/stop logic that was copied verbatim into `ButtonBetProvider` and `Game.svelte`). Skipping never DROPS a beat: every book event still runs, fully awaited, and applies its effect at final value — only the time is removed. **Two presentations are carved out as UNSKIPPABLE** (`apps/lines/src/game/unskippablePresentation.ts`): the book / expanding-symbol reveal (`setExpandingSymbol`) and the free-spin intro (`freeSpinTrigger`) run to completion, because their visual is a spine/`.irig` timeline that a released wait leaves playing detached over the next spin. Their player-gated tap holds still release on a slam (a slam makes the spin button inert, and it swallows the tap). **A slam is not a blank:** a slammed spin that WON keeps a minimum win display — the lit win symbols and the per-win info message, ~600ms each — while the win line and the amount count-up stay fully skipped. **The press has its own SOUND:** a mid-round press broadcasts `soundPressStop` (`sfx_btn_stop`) instead of the bet whoosh — ⚠️ currently a STAND-IN region, see open item 5. **Celebration lock:** during a non-skippable celebration — free-spin **intro**, free-spin **outro**, or **big win** — the spin button goes fully inert (it can't slam-skip the celebration); it renders as a greyed STOP. Driven by `stateUi.hasCelebrationOverlay()` (`bigWinShow || freeSpinIntroShow || freeSpinOutroShow`, set on every dispatch path — coded/flow-v1/flow-v2), read at the single chokepoint `utils-shared/spinStop` (`getSpinButtonKey` → new `stop_disabled` key; `runSpinOrSlamStop` early-returns as belt-and-braces for the flow `spin` action / Space hotkey / intent callers; new `isSpinButtonDisabled` helper de-dupes the disabled check across `ButtonBetProvider`, the authored HUD `spin` action + Space hotkey in `Game.svelte`). A REGULAR win count-up (`winShow` without `bigWinShow`) is deliberately still slammable. The disabled button's canvas rect still swallows a tap in its footprint (Pixi `eventMode` stays `static`), so a press-to-continue tap that lands exactly on the button does nothing rather than advancing — accepted (small dead-zone; the rest of the screen still advances). Verified: `apps/lines` compiles + boots clean with the change; a live big-win/free-spin reproduction was not scripted.
- **Live-asset pipeline** — a game asset only ships when it travels the full chain **export → `deploy/` → bake (embed index in bundle) → pull (mirror into `static/assets/`) → runtime register** (CLAUDE.md rule 8; `docs/design/live-assets.md`). Exported sheets are content-versioned (`sheetVersion` hashes region geometry + source-page ETag) so a re-packed atlas busts the cache automatically; exporters emit a `missing[]` dangling-binding guard. "Shows in the editor" ≠ "ships" — the editor reads R2 directly.
- **How the runtime ships** — an engine/runtime change reaches online games ONLY via a runtime-bundle publish, NOT a `main` merge. **Preferred: the `Runtime release` GitHub Action** (`.github/workflows/runtime-release.yml`) — a manual `workflow_dispatch` ("Run workflow", or `gh workflow run runtime-release.yml -f runtime=lines`) that does the whole chain with the R2 keys held in GitHub Actions secrets, so a release needs no keys on a dev machine. Game Maker's Publish CANNOT do it: `publishGame` only points a game's manifest at the prebuilt `_runtime/<id>` and "never rebuilds". The equivalent manual chain: rebuild the `engine-layout` **dist** first (stale-dist trap), then `PUBLIC_RGS_TRANSPORT=play4fun pnpm --filter lines build`, then `node apps/launcher-api/scripts/publish-runtime-bundle.mjs lines apps/lines/build`, then `POST https://games.invisiblewall.org/refresh`. Shipped standalone games (e.g. Book of Borut) instead bump their `engine` git submodule to a `main` commit (owner-owned). Standalone Borut keeps its OWN `src/game/*` copies, so game-side wiring (flags/effects/constants) must be MIRRORED there — the submodule only delivers `packages/*` engine code.

⏳ Live-verify caveats still open: `SYMBOL_SPINE_FILL`'s live size judgement (0.5 tunable); the z-order of author extra-scenes (currently above the HUD) is a live tuning call; the win-line line-draw and sequential-stop timing were shipped + reachability-verified but not auto-verified in a live spin (owner confirms by forcing the win / triggering free spins).
