# Invisible Component Editor — status

> Design: [docs/design/invisible-editor.md](../design/invisible-editor.md) (§8) · Guide: [docs/tools/component-editor.md](../tools/component-editor.md) · Agent: `.claude/agents/invisible-components.md` (component-focused; not a registered spawnable agent)
>
> Companion tool: [Scene Editor status](./editor.md) — that tool **places** component instances; this tool **authors** the `ComponentDef`s (and reuses the Scene Editor's canvas/outline/properties machinery).

**One-line state:** Built — component authoring (instances/params/signals) + the per-project **"This game's defaults"** surface (2026-09-17) + pin-by-default versioning with a true multi-version store and version browser are on `main` at `/components`, registered + documented; ⏳ the **behaviour/timeline** layer is unbuilt (this is the *declare* half only), and editor render paths are largely not browser-verified.

## Current state
Standalone authoring tool for **components** (prefabs) at `/components` — launcher-native, full-page, SSR off, gated on the **`editor`** tool (the `componentEditor` tool entry only controls the home-grid card). Components load for the active client/project (project shadows shared shadows built-in); **Save** always writes a project-scoped component.

Shipped capabilities on `main`:
- **Author a component** — create Blank (`UI`/`Overlay`/`Scenery`) or a pre-wired **Button** (pre-declares the `action` param); build the `root` element tree on the shared editor canvas (Text/Rect/atlas/spine/sheet regions), outline + properties reused from the Scene Editor. Deep-linked from the Scene Editor's "Open Component Editor" / "Edit as component".
- **Declare the engine contract** (the "Component variables" block) — **Engine params** (curated catalog: bet/win/balance/…), **Your params** (custom author inputs: string/image/number/color/boolean, with per-param defaults, bound to a node's image/tint/text/font/size/colour), and **Engine signals** (named moments; declare-only). Text nodes have an **Expose as params** shortcut.
- **Per-instance engine bindings** (Flow-driven-game Phase 6, 2026-06-30) — any placed instance can be made clickable (`action`) or lifecycle-gated (`visibleSource`) without the def declaring the param (shared `engineBindings.ts` + an "Engine bindings" tray in `EditorProperties`); UI for `visibleFor` / `screenAnchor` / custom-param `options`; and **per-instance signal rebinding** (`cueSignalOverrides` — override which engine signal drives a spine cue, e.g. `win` vs `bigWin`).
- **Button-state-driven spine animations** (2026-06-25) — `SpineNode.stateAnimations` (hover/pressed/selected/disabled/spinning cascade), authored via "Plays on button state"; blank-default spine = a state-only overlay over a resting button image.
- **Versioning** — pin-by-default with a **true multi-version store** (v2): a changed save bumps `version` AND retains every historical `<id>.v<N>.json` snapshot, so an instance resolves the EXACT def it pinned (editor preview, bake, and shipped game); a missing pin renders latest + a `versionMismatch` warning, never a silent upgrade. Outdated instances are **flagged** in the Scene Editor and updated per instance (never bulk). A **version browser** (top-bar `Version` dropdown + **Inspect** read-only + **Back to latest**) browses retained snapshots non-destructively.
- **Promote to shared** (2026-06-24) — holders of the `componentPublish` capability (admin by default) get a top-bar button writing a `_shared/editor-components/<id>.json` snapshot; enforced server-side. The kept draft stays project-scoped and still shadows the shared copy.
- **"This game's defaults"** (2026-09-17, design Phase B3) — a second panel under *Component variables* setting the open def's params for the ACTIVE PROJECT only, stored in the §13.3 sidecar (`editor/<project>/component-defaults/<id>.json`) so a SHARED def can look different per game without being forked. Lists every `!engineProvided` param with the instance panel's widgets; empty = inherit (the key stays absent, `×` restores it); its own `SaveState` + **Save for this game** + conflict badge, separate from the def's versioned save. Both editor canvases resolve it (see [editor status](./editor.md)).

## Open items / next
1. **Behaviour / timeline layer (§8.5–8.7) — the next large phase, unbuilt.** Signal-triggered tweens, spine playback, particle bursts, and a single count-up data binding are designed (`BehaviorTrack`/`TweenStep`) but not authorable here yet; the `Component variables` block is purely the *declare* half. No per-signal track UI exists. v1 behaviour ceiling is intentionally low; anything needing branching/RGS math/stateful logic stays a coded `mount`.
2. ✅ ~~**B4 HUD migration**~~ — **DONE for `apps/lines` (shipped 2026-06-08):** the live Balance/Win/Bet readouts render as `hudReadout` component instances behind the parity gate. Remaining tail: the **Borut mirror (B4.6)** submodule bump + owner live-verify.
3. **Nesting depth capped at 2** (`MAX_COMPONENT_DEPTH`, cycle-guarded) — widen only when a game needs it; the bake walks only top-level scene pins, not the transitive nested-pin closure (no game pins a nested version yet).
4. **Authoring gaps** — no autosave (unsaved drafts are in-memory only, discarded on close with a warning; "This game's defaults" is a second, separate manual save); authoring a SHARED component as its only copy, and a promote-from-Library-row affordance, are not built.
5. **A per-project default only reaches a built game on its next publish/bake** — the bundle carries the map, so changing a default in the tool does not retroactively change an already-published game.

## Blocked (owner / external)
- **Engine submodule bump required for shipped games** — component/engine changes reach Book of Borut only after its `engine` submodule is bumped + the game rebuilt (owner-owned).
- **Live-verify** — component render paths (state animations, version resolution, instance rebinding) build clean and type-check but are largely not browser-verified on the auth-gated canvas; owner confirms live.

## Recent changes

- 2026-09-18 — **The shared component library was pinned to ONE project's art, and every other game shipped that art as nothing.** Found from a live `waysofwavesbuild` console error (`Spine: key "invisible_wall/bookofborutremake/spines/R_Cage_Freespin/" is not found in loadedAssets`) and then swept across all of R2: **six** `_shared/editor-components/` defs named a bundle under `invisible_wall/bookofborutremake/` (one under the older `borut/bookofborut/`). A shared def is resolved by EVERY project, but the export only resolves a bundle in the reading project's own `spines/` root or `_shared/spines/` — so for everyone except the project that authored it the art ships as nothing and the game throws at the lookup. **Seven projects place `freeSpinCounter`; six of them were getting the broken cage.** No scene doc was affected — this was purely the shared library.
  - **Why only one of them was reported.** A spine node whose `assetKey` is bound to a `spine`-kind param never uses its static key: `Button_Square`'s `rspinbuttonnewSpine` is set by all six placements, so its identical foreign key is inert residue. `freeSpinCounter`'s node had no binding, so the foreign key WAS the lookup. Same pin, two outcomes — which is why "the spin button works" said nothing about the cage. `featureCard`, `freeSpinIntroVisual`, `freeSpinOutroVisual` and `transition` carried the same live pin, unreported only because no project had placed them yet.
  - **The guard.** `saveComponent` now refuses a def whose spine node points into a project other than the saving scope's own (`assertNoForeignSpineRefs`, using `parseSpineBundleKey`). `_shared/spines/` stays allowed everywhere — that IS the supported way to borrow, and `sharedSpinePromote`'s "COPY, DON'T REFERENCE" is the same reasoning one level down. A project def keeps its own bundles; a bare/coded key is untouched. The message names the promote path rather than just refusing.
  - **The repair, two moves.** `freeSpinCounter`'s shared v4 *is* Borut's counter (built-in frame sprite deleted, texts moved down, cage added), so it FORKS to `editor/bookofborutremake/components/` — where the same `assetKey` is a local reference — and the shared entry returns to the engine's built-in, which the other six projects already expect. The rest PARAM-ise instead: the hardcoded node's `assetKey` binds to a new `spine` param defaulting to the bare bundle NAME, which the export reconstructs against the READING project's root, so Borut resolves exactly what it does today while the shared def stops naming any project. That is the pattern the library already uses, and it avoids reverting customisations other projects may rely on.
  - The transport half (why the miss was silent at all) is in [launcher status](./launcher.md) (2026-09-18).

That is exactly the case the sidecar exists to fix: vary a SHARED def per game without forking it.
  - **The panel** (`EditorProperties.svelte`, component mode only, under *Component variables*): every `!engineProvided` param of the open def, grouped by `p.group`, with the same widgets the Scene Editor's instance panel uses (`RegionPicker scoped` / `ColorField` / font `<select>` / `p.options` dropdown / live `action` catalog / checkbox / number / text). Deliberately NOT built off `variableRows` — that list is engine-catalog subscriptions + `author: true` params only, which on the live HUD Readout is **1 of its 20** settable params. Empty = **inherit**: the control reads `(inherit default: x)` or placeholders the def's own default, the key is ABSENT from the saved map, and a `×` (shown only when this game stores a value) puts it back. Hidden with no active project, and while inspecting a historical version.
  - **Its own save.** A second `SaveState` + `SaveStatusBadge` + **Save for this game**, NOT folded into the draft's `saveState`: different R2 key, different ETag, and the ordinary shared conflict badge (Reload theirs / Overwrite with mine) rather than the draft's bespoke versioned `confirm()` — same reasoning that already keeps promote-to-shared separate.   - **The preview is WYSIWYG both ways.** The Component Editor canvas resolves `resolveComponentParams(draft, undefined, projectDefaults)` and repaints as you type; the Scene Editor canvas was threaded in the same change (see [editor status](./editor.md)).

Author-created components (`c_xxxxxxxx`) were never affected. **Rule 8 applies here** — "it shows in the editor" would not have meant it ships.

- 2026-09-17 — **Review follow-up: a lost update that defeated the sidecar's own CAS, plus the slug mismatch fixed at its source.** Shipped in #722 and corrected immediately after (#723); exposure was nil because no sidecar existed in R2 yet.
  - **The lost update.** `loadProjectDefaults` adopted the server's ETag and then, if the author had typed during the round-trip, KEPT the local values. A save replaces the map wholesale, so that write passed `If-Match` under someone else's version marker and deleted every key it had never seen — silently, with no 409 and no banner. Two authors on one component was enough; no staleness required. The etag is now adopted only on the branch that also adopts the values, so a raced save holds `null`, asserts create, 412s, and surfaces a real conflict. (`adoptEtag` also resets the status machine to `idle`, so the old placement could clear an already-raised conflict too.)
  - **The stale seed.** The page-load map was used as the open-seed AND was never invalidated, so after the first save in a tab every re-open seeded pre-save values; with a failed GET, "Overwrite with mine" would then force-write them over the author's own work. It is now an explicitly paint-only `seededDefaults`, refreshed by every successful load and save. A failed GET no longer returns silently — it reports, so "reload theirs" can't read as a no-op while the sticky conflict pill stays up.
  - **The slug mismatch, fixed at source.** `saveComponentDefaults` now STAMPS the real `ComponentDef.id` in the sidecar (`{ id, params }`) and `listComponentDefaults` keys off it, so the lossy `r2Slug` filename stops mattering everywhere at once. `keyComponentDefaultsById` stays as the fallback for sidecars written before the stamp. This also closes the gap where `/api/editor/doc`'s lean boot path aliased only TOP-LEVEL scene ids, so a component nested inside another def's root never resolved its defaults. The sidecar reads also went concurrent (`Promise.all`) — that loop is now on the Scene Editor's page-load path.
  - **The panel no longer contradicts its own canvas.** `instanceParamEffective` skipped the project layer, so an unset control in the Scene Editor's instance panel read the def's default while the canvas drew the project's — a boolean defaulted `true` by the project drew ticked and read unticked, and ticking it wrote a redundant explicit override. It now mirrors `resolveComponentParams` exactly.
  - **Guards:** switching components in the sidebar (the most common way to leave one, and the only exit with no guard) now asks before discarding dirty defaults; entering an inspect resets them after its warning, instead of stranding them behind a hidden panel whose Save button had gone with it.
